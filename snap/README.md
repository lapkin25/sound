# sound

**Бит-в-бит вычислительная среда с линейным журналом, снапшотами и кросс-хост-реплеем.**

Sound — это жанр вычислений, в котором ответ обязан быть функцией *записи*, а не настроения
компилятора. Каждая операция вычисляется по факту применения и попадает в append-only журнал;
каждое число канонизируется в 16 hex-цифр IEEE-754; любое расхождение между двумя графами
вычислений не сглаживается «примерно равно», а звенит проводом — диссонансом.

Проект начался с одного вопроса: *сколько будет 1000 под 5% на три года?* — и обнаружил,
что честных ответа два: `1157.625` ровно (граф `((1000×1.05)×1.05)×1.05`) и
`1157.6250000000002` (наивная перегруппировка). Оба безупречны по IEEE. Sound не выбирает
«правильный» — он делает выбор видимым, записываемым и проверяемым.

## Быстрый старт

Требования: Python 3 (только стандартная библиотека), GNU Octave для кросс-хоста.

```bash
# весь стек одним следом: ядро, снапшоты, зеркало Octave-пути,
# регистры, двойная запись, отчёт + манифест хешей
python3 sound_all.py

# только ядро и снапшоты (создаёт snap_A.json и snap_B.json)
python3 sound_snap2.py

# три примера жанра: вклад, мини-учёт, провода
python3 examples.py

# кросс-хост-реплей: сессия, рождённая в Python, продолжается в Octave
# (запускать из корня репозитория, после sound_snap2.py)
octave --eval "run('octave/replay_octave.m')"

# ожидаемый финал кросс-хоста:
# ALL PASS: сессия Python продолжена в Octave
```

`make all` — то же самое одним словом; `make octave` — кросс-хост; `make clean` — удалить
`artifacts/` и `__pycache__/`.

## Архитектура

```
документ (вектор фактов)
    ↓ инвариант суммы + провод против Fold   ← звено 6
регистр (дерево версий снапшотов)            ← звено 5
    ↓ снапшот = версия: имена по битам, AST функций, журнал, отпечаток
слой WL: Set/SetDelayed, Nest/Fold/Table, If  ← звенья 1–3
    ↓ каждая операция = строка журнала tN op(...) -> hex
ядро Sound: канон битов, право-ассоциативность ← звено 0
    ↓ реплей и сверка
любой хост (Python, Octave, …)                ← звено 4
```

Полный цикл учёта: **документ → регистр → отчёт**. Каждый шов закрыт проверкой:

- аудиторский реплей воспроизводит любую версию из предка в свежей сессии;
- подделка одной строки журнала взрывает цепочный отпечаток;
- отклонённая проводка или несбалансированный документ не оставляют ни версии,
  ни строки журнала — недопустимая ветвь не существует;
- провода сверяют учёт с независимыми графами расчётов.

## Форматы

Канонические спецификации — в `docs/formats.md`; ниже — выжимка.

### Строка журнала

Каждая вычисленная операция — одна строка, append-only:

```
t75 /(4006a09e667f3bcc,4000000000000000) -> 3ff6a09e667f3bcc
t1  set(x) -> 4000000000000000
```

Формат: `tN op(аргументы через запятую) -> результат`, все числа — ровно 16 hex-цифр
big-endian IEEE-754. Номер `tN` глобален по всей истории сессии, включая снапшоты:
журнал потомка обязан продолжать журнал предка посимвольно.

### Снапшот (формат `wl-snap-1`)

```json
{
 "version": "wl-snap-1",
 "names":   {"x": "4000000000000000"},
 "funcs":   {"step": {"params": ["x"], "body": {"kind": "op", ...}}},
 "journal": ["t1 set(x) -> 4000000000000000", "..."],
 "last":    "3ff6a09e667f3bcc",
 "fingerprint": "0fad1318..."
}
```

- имена — по битам, а не по представлению: восстановление не зависит от хоста;
- функции — как AST, воспроизводимы на любом хосте;
- `last` — результат последнего стейтмента (по нему сверяется реплей);
- `fingerprint` — **цепочный отпечаток**: `fp = sha256(fp_пред + строка)`, старт с 64 нулей.
  Восстановление с несовпавшим отпечатком поднимает ошибку — тихо исказить журнал нельзя.

### Манифест

`sound_all.py` после прогона пишет `artifacts/sound_manifest.json`:
sha256 каждого файла стека и **стековый отпечаток**, посчитанный той же цепочкой,
что и отпечаток журнала — связка слоёв друг за другом.

## Законы жанра

Полные формулировки с обоснованиями — в `docs/invariants.md`. Кратко:

1. **Бит-в-бит, а не «примерно».** Проводы сравнивают 16 hex-цифр и слышат соседний ulp.
2. **Журнал append-only, ядро stateless.** Каждая строка сессии — чистый запуск ядра;
   состояние живёт только в именах.
3. **Право-ассоциативность.** `a - b - c` значит `a - (b - c)` — следствие линейного журнала.
   Вычитание и деление рекомендуются в явной функции или скобках.
4. **Запрет реассоциации.** Перегруппировка слагаемых меняет биты — и это не баг, а честность:
   ответ есть функция записи. Провод звенит на любом расхождении графов, даже легитимном.
5. **Атомарность документа.** Вектор фактов проходит черновую сессию целиком или не существует.
6. **Недопустимая ветвь не существует.** Инвариант считается до касания журнала регистра.
7. **Аудит независим.** Реплей — свежая сессия; сверка посимвольно и по `last`.
8. **Отчёт не трогает журнал.** Ведомость считается в чистой сессии над снапшотами.
9. **Канон графа.** Ведомость считается тем же графом, что регистр; агрегатный граф —
   независимый страж, обязанный звенеть на переассоциационных данных (см. пример ниже).

## Жемчужины — что доказано прогонами

- **Собственная фиксированная точка Ньютона.** Итерация `(x + 2/x)/2` сходится от четырёх
  разных стартов в одно и то же место — `0x3ff6a09e667f3bcc`, на 1 ulp *ниже* корректно
  округлённого `math.sqrt(2)` (`…3bcd`). Это свойство дискретного отображения в IEEE:
  наше значение воспроизводимо из определения, на любой машине и в любом рантайме.
- **Петля фиксированной точки в журнале** (t73 → t75): `2/√2` округляется в соседний ulp,
  а усреднение возвращает — отображение замкнулось на себе, это видно прямо в строках.
- **Вклад**: `Fold` даёт `1157.625` ровно; наивная `1000.0*1.05**3` — соседний ulp.
- **Стресс ведомости**: три документа по `0.1` — регистровый граф даёт ровно `0.2`,
  агрегатный `0.20000000000000004`. Провод звенит на двух безупречных графах —
  измеренное обоснование для будущего типа «целые копейки».

## Регистры, двойная запись, отчёт

`ledger.py` — регистр как дерево версий снапшотов: `commit(label)`, `checkout(vid)`,
проводка через инвариант-шлюз в чистой черновой сессии, аудит-реплей, префикс-непрерывность
цепочек, тампер-тест.

`accounting.py` — документ как вектор фактов `[(счёт, дельта), ...]`: положительная дельта —
дебет, отрицательная — кредит. Инвариант сохранения суммы и провод против Fold решают судьбу
документа до касания журнала. Саботажный документ (дебет 400, кредит 250) отклоняется и не
порождает версии.

`report.py` — оборотно-сальдовая ведомость: «сальдо конечное = сальдо начальное + дебет +
кредит» бит-в-бит, глобальная сверка «сумма дебетов = сумма кредитов».

## Кросс-хост-реплей

Сценарий: Ньютон в Python → снапшот A (31 строка) → продолжение → снапшот B (76 строк) →
возврат в A → реплей продолжения. Octave-раннер восстанавливает сессию из снапшота,
**вычисляет продолжение заново** и сверяет со снапшотом B: журнал посимвольно, `last`
по битам. Номера t-биндов Octave считает независимо — если бы порядок операций или
округление отличались хоть на йоту, `strcmp` упал бы на первой же строке.

Доказано на живых машинах: `ALL PASS` в Python и Octave.

**Честная граница:** тело `step` в раннере закодировано явно — раннер есть независимая
реализация семантики, но специализирован под сценарий. Универсальный интерпретатор AST
в Octave — следующий рубеж (см. `docs/roadmap.md`).

## Расширение

- **Новая встроенная функция**: добавить ветку в `Session.builtin` в `sound_snap2.py`
  со строго фиксированным порядком биндов — грамматика вызовов уже общая.
- **Новый хост** (Octave, Excel, что угодно): нужно реализовать ровно три вещи —
  1) канонизацию битов в 16 hex-цифр (в Octave: `num2hex`),
  2) восстановление битов (little-endian typecast-путь),
  3) вычисление в том же post-order с тем же форматом строк журнала.
  Всё, что между, — уже стандартизировано форматом снапшота.
- **Новый отчёт**: любой чистый граф над снапшотом; провода сверяют его с регистром.

## Границы и известные ограничения

Честный список, ничего не спрятано:

- деньги — в даблах; для дробных сумм класс проблемы реассоциации измерен стрессом
  ведомости. Решение — тип «целые копейки» — в дорожной карте;
- имена допускают кириллицу внутри, но не первым символом (класс лексера);
- хвостовое подчёркивание в имени зарезервировано под параметры паттерна (`f[x_]`);
- голое выражение должно начинаться с имени — константное пишется через присваивание;
- символьной математики, паттернов глубже `x_` и удержания вычисления (`Hold`) нет —
  ядро числовое, и слой это честно отражает;
- `Fold`/`Table` — строго последовательные; параллелизм несовместим с линейным журналом;
- NaN канонизируется без payload — сверяйте NaN-значения по битам;
- манифест доверяет честности носителя: связка хешей есть, подписей пока нет.

## Дорожная карта

1. **Целые копейки** — домен документа: целочисленный тип с запретом сырого деления.
2. **Универсальный AST-интерпретатор Octave** — кросс-хост без специализированного тела.
3. **Подписи манифеста** — внешняя передача снапшотов с доказуемой подлинностью.
4. **Документы с датой/номером** — снапшот как строка главной книги.
5. **Excel-бэкенд** — ядро Sound в формулах книги (ранее обсуждённое звено).

## Глоссарий

- **журнал** — линейный append-only след всех вычислений сессии;
- **t-bind** — одна строка журнала: операция, аргументы и результат в канонических битах;
- **провод** — сверка двух графов по битам; **диссонанс** — его звон при расхождении;
- **снапшот** — самодостаточное состояние сессии: имена по битам, AST функций,
  журнал, отпечаток;
- **отпечаток** — цепочка sha256 по журналу; молча исказить журнал нельзя;
- **регистр** — дерево версий снапшотов с инвариант-шлюзом;
- **документ** — атомарный вектор фактов, дебет/кредит;
- **хост** — рантайм, способный вычислять по канону и сверяться реплеем.
