# Чек-лист конформанса Octave-реализации Sound v0.2

Формат fixtures: `sound-fixtures-1`. Файл `fixtures_sound.json` кладётся в
один каталог с реализацией. Прогон: `octave --eval conform_octave`,
ожидаемый хвост: `ALL PASS (41/41), skips: 11`.

## 0. Контракт узла (§8.2) — до запуска векторов

- [ ] каждое правило спеки экспонировано как функция: `спека_правило`
- [ ] факты — константы только для чтения, файл `спека_facts.m` возвращает struct
- [ ] обмен между процессами — только TRIOMAT1 (вариант Б), байты, а не нативные структуры
- [ ] ошибки возвращаются только из закрытого набора из 19 кодов (сверка: `fx.codes`)
- [ ] инвариант правила проверяет реализация; нарушение -> `DomainError` с деталью «имя-правила: инвариант»
- [ ] журнал побайтно идентичен эталону: `bind имя = значение`, `result`, `err КОД [деталь]`
- [ ] канон float сверён на векторах C01–C12, а не на «похожести»
- [ ] запрещено: fast-math, переассоциация операций, FMA,
      промежуточные вычисления ниже объявленной точности, локаль в форматировании чисел

## 1. Канонический float (§6.4) — векторы C01–C12

- [ ] double из `hex_bits` собирается как два 8-значных полубайта
      (uint64 + bitshift + typecast): `hex2dec` 16 цифр сразу теряет точность
- [ ] спец-ветки nan / inf / -inf / ±0.0 проверяются до нормализации мантиссы
- [ ] знак нуля различается: через `1/x < 0` (-0.0 -> `-0x0.0p+0`)
- [ ] денормалы: отдельная ветка `0x0.С…p-1022` при e == -1023 (вектор C12)
- [ ] нормальные числа: `0x1.` + 13 hex-цифр мантиссы + `p+экспонента`
- [ ] нибблы строчные: `tolower(num2hex(x))`
- [ ] знак экспоненты: `+` для неотрицательных, `-` для отрицательных

## 2. Сборка TRIOMAT (векторы M01–M05)

- [ ] рамка: `MAGIC(8) | hlen(4, uint32 LE) | JSON-заголовок | payload`
- [ ] заголовок — компактный JSON: `{"dtype":"Float64","shape":[2,2]}`
- [ ] payload — C-порядок логических значений; для 2-D линейзация через `x.'(:)`
- [ ] собранный файл байт-в-байт совпадает с `base64` из fixtures (T2-аналог)
- [ ] вариант Б: F- и C-хранилища одного массива дают один файл

## 3. Разбор TRIOMAT и 9 проверок ридера (векторы X01–X08)

- [ ] порт `trio_bridge._parse`: MalformedHeader / MalformedDtype /
      MalformedPayload / MalformedShape / TypeMismatch
- [ ] ридер 9 проверок: ранний выход на 01, 02, 04, 05, 07; 03, 06, 08 — не прерывают
- [ ] Bool: сырые байты валидируются до декодирования; байт вне {0,1} -> TypeMismatch
- [ ] 2-D reshape: C-порядок байтов -> логические значения (транспонированный reshape)
- [ ] сводка по R-ERR2: ошибка доминирует над Lossy, пустой набор -> ResourceLost
- [ ] Float16 — резерв этапа 2 (в fixtures v1 не используется)

## 4. Арифметика ядра (векторы A01–A16)

- [ ] целочисленное деление: `idivide(a, b, "fix")`; обычный `/` на int64 даёт
      double — запрещён; режимы "round" и "floor" — запрещены
- [ ] `%` — знак делимого, семантика Python: `mod(x, y)`
- [ ] переполнение int64 ловится по знакам результата до/после операции:
      Octave заворачивает молча, тихая усадка запрещена
- [ ] особый случай: `intmin('int64') / -1` -> IntRangeOverflow
- [ ] IEEE-деление на ноль: `x/0.0` при x != 0 — знаковое inf через copysign;
      `0.0/0.0` -> NaNOutsideDomain
- [ ] NaN-ветки: inf-inf, inf*0, inf/inf -> NaNOutsideDomain
- [ ] mixed (int + float): подъём к double; флаг lossy на границе 2^53-1 включительно
- [ ] большие целые приходят строкой (`int_str`) — не через парсер чисел

## 5. Журнал (векторы J01–J07) — этап 2

- [ ] знак `=` только у `bind`; `result` и `err` без `=`
- [ ] временные узлы `t0, t1, …` — только для числовых промежуточных значений
- [ ] float в журнале — в канон-форме §6.4
- [ ] одинаковый вход -> побайтно одинаковый журнал
- [ ] в `conform_octave.m` помечены SKIP: проверяются на этапе 2 (обвязка узлов)

## 6. Числовые обязательства хоста Octave (§8.4)

- [ ] `idivide(a, b, "fix")` для целочисленного деления
- [ ] проверка диапазона перед каждой int64-операцией (int64 переполняется молча)
- [ ] `tolower(num2hex(...))` при сборке канона
- [ ] C-порядок при упаковке payload (нативная матрица column-major)
- [ ] никаких `printf`/`sprintf` с локалью для канонов и журналов

## 7. Вне конформанса v0.2

- [ ] статические проверки (SC1–SC4): фиксированный порядок SC-002 -> SC-060;
      SC-061 зарезервирован и недостижим из грамматики; сверка — на эталоне Python
- [ ] замыкания и частичное применение: векторах `scope: core` — эталон Python;
      Octave-узел обязан только вести журнал и соблюдать типы
- [ ] компоновщик `sound.nodes` не реализован: провода проверяются статически
      (SC-060), но не исполняются; межузловые TRIOMAT-обмены — вне v0.2
- [ ] пути с пробелами в манифесте не поддерживаются
