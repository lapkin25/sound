# Sound + TRIOMAT — документация v0.2

Маленький декларативный язык спецификаций с исполняемым ядром и собственным
форматом сериализации. Четыре слоя, каждый используется отдельно.

## 1. Состав пакета

| Слой | Файл | Ответственность |
|---|---|---|
| Мост | `trio_bridge.py` | формат TRIOMAT1, канон float, приведения, агрегация |
| Ядро | `sound_core3.py` | значения, IEEE-арифметика, замыкания, журнал |
| Фронтенд | `sound_front.py` | лексер, парсер, канон-сериализация, статические проверки |
| Ридер | `sound_reader.py` | чтение `.tri`-файлов, 9 проверок целостности |

Поток: текст спеки → фронтенд → ядро → мост → ридер.

Зависимости: Python 3.8+, numpy. Всё в одном каталоге.

## 2. Быстрый старт

Содержимое `demo_sound.py` — единственный скрипт, покрывающий весь стек.
Все выводы ниже — фактические, снятые с прогона этой версии.

```python
# demo_sound.py
import numpy as np
import trio_bridge as tb
import sound_core3 as C
import sound_front as F
import sound_reader as SR

# --- мост: сериализация и канон ---
m = np.array([[1., 2.], [3., 4.]])
print(tb.read_matrix(tb.write_matrix(m)))   # OK(array([[1., 2.], [3., 4.]]))
print(tb.canon_float(3.0))                  # 0x1.8000000000000p+1
print(tb.canon_float(-2.25))                # -0x1.2000000000000p+1
print(tb.int_check(2**53 - 1))              # Lossy(n=9007199254740991)
print(tb.int_check(2**63))                  # Err(IntRangeOverflow, '...')
print(tb.to_int_exact(1.5))                 # Lossy(n=2)
print(tb.aggregate([tb.Lossy(1), tb.Err("Timeout")]))  # Err(Timeout)

# --- ядро: арифметика, журнал, замыкания ---
r = C.Run()
val = C.run(["let", "x", ["lit", 2], ["+", ["sym", "x"], ["lit", 3]]], r)
print(val.j())   # Int64 5
print(r.log)     # ['bind x = Int64 2', 'bind t0 = Int64 5', 'result Int64 5']

print(C.run(["/", ["lit", 1.0], ["lit", 0.0]]).j())    # Float64 inf
print(C.run(["/", ["lit", -1.0], ["lit", 0.0]]).j())   # Float64 -inf
print(C.run(["/", ["lit", 0.0], ["lit", 0.0]]).code)   # NaNOutsideDomain
print(C.run(["/", ["lit", 3], ["lit", 0]]).code)       # DivisionByZero
INF = float("inf")
print(C.run(["-", ["lit", INF], ["lit", INF]]).code)   # NaNOutsideDomain
print(C.run(["/", ["lit", -3], ["lit", 2]]).v)         # -1 (усечение к нулю)

C.register_fn("add", ["a", "b"], ["+", ["sym", "a"], ["sym", "b"]])
g = C.call_fn(C._mk_clo("add", C.REGISTRY), [C.VInt(100)], C.Run())
print(C.call_fn(g, [C.VInt(5)], C.Run()).v)            # 105 — частичное применение

# --- фронтенд: спека, roundtrip, статические проверки ---
SPEC = (
    "spec mixer ;\n"
    "fact gain 2 ;\n"
    "wire src -> scaled ;\n"
    "rule scaled x = x * gain ;\n"
    "pure rule trim x: Matrix[2,2] = x * 0.5 invariant x >= 0 ;\n"
)
sp = F.parse_spec(SPEC)
print(F.roundtrip(SPEC))      # True
print(F.serialize(sp))        # см. вывод ниже
print(F.static_checks(sp))    # [] — спека корректна

# --- ридер: сквозной прогон ---
res = SR.read_file(tb.write_matrix(np.array([0.5, -1.25, 2.0])))
for name, rr in res: print(name, rr)
print(SR.summary(res))        # OK()
```

Вывод `F.serialize(sp)`:

```

wire src -> scaled ;
rule scaled x = x * gain ;
pure rule trim x: Matrix[2,2] = x * 0.5 invariant x >= 0 ;
```

Вывод блока ридера:

```

03 hlen-sane OK()
04 header-json OK({'dtype': 'Float64', 'shape': [3]})
05 dtype-known OK('Float64')
06 shape-ints OK([3])
07 payload-size OK()
08 bool-bytes OK()
09 decode OK(array([ 0.5 , -1.25,  2.  ]))
OK()
```

## 3. Синтаксис языка Sound

Спека — один файл, пункты в любом порядке.

```
spec имя ;

fact имя арг1 арг2 … ;                     # константа
wire имя -> приёмник [ : Тип ] ;           # связь; тип опционален
[модификаторы] rule имя парам… = тело [ invariant условие ] ;
```

- Модификаторы: `pure`, `safe` — в любом порядке до `rule`.
- Параметры — **через пробел**, тип опционален: `x` или `x: Matrix[2,2]C`.
- Приоритеты тела: сначала `== != < > <= >= ?`, затем `+ -`, затем `* / %`;
  скобки группируют.
- `in` и `invariant` — ключевые слова: имя `in` объявить нельзя.
- Хвостовая `;` в заголовке спеки опциональна.

## 4. Ядро

### Значения и журнал

| Тип | Конструктор | Журнал |
|---|---|---|
| nil | `VNil()` | `nil` |
| булево | `VBool(True)` | `Bool true` |
| целое | `VInt(5)` | `Int64 5` |
| float | `VFloat(3.5)` | `Float64 0x1.c000000000000p+1` |
| строка | `VStr("hi")` | `Str "hi"` |

Журнал детерминирован: `bind имя = значение` (знак `=` — только в bind),
`result значение` (без `=`), `err Код`. Терм-узлы нумеруются `t0, t1, …`.

### Семантика арифметики

- IEEE-деление float: `1.0/0.0 → +inf`, `-1.0/0.0 → -inf` (знак через
  `copysign`); `0.0/0.0` и `inf/inf` → `NaNOutsideDomain`.
- NaN-чек во всех ветках: `inf − inf`, `inf * 0` → `NaNOutsideDomain`.
- Целочисленное деление — **усечение к нулю**: `3/2 → 1`, `-3/2 → -1`.
  Реализация чисто целочисленная (`//` со знаком) — точна на всём Int64.
- `1/0` → `DivisionByZero`. Целочисленное переполнение → `IntRangeOverflow`.
- Сравнения для чисел и строк; несовместимые типы → `TypeMismatch`.
- `widen_lossy`: смешение Int/Float → Float; целое с `|n| ≥ 2⁵³−1` помечается
  lossy.

### Замыкания

```python
C.register_fn("add", ["a","b"], ["+", ["sym","a"], ["sym","b"]])
g = C.call_fn(C._mk_clo("add", C.REGISTRY), [C.VInt(100)], C.Run())
C.call_fn(g, [C.VInt(5)], C.Run()).v   # 105
```

Замыкание захватывает окружение **в момент обращения к имени**. Частичное
применение переносит биндинги парами `(имя, значение)`; свободные параметры —
`params[len(bindings):]`.

## 5. Статические проверки

Закрытый порядок, первый по порядку код подавляет остальные:
**SC-002 → SC-061 → SC-060**.

| Код | Условие |
|---|---|
| SC-002 | правило ссылается на имя не из параметров и не из спеки |
| SC-061 | инвариант объявлен не у правила |
| SC-060 | провод ведёт к необъявленному имени |

```python
F.static_checks(F.parse_spec("spec s ; wire A -> B ;"))   # ['SC-060']
F.static_checks(F.parse_spec("spec s ; rule r x = q + 1 ;"))  # ['SC-002']
```

## 6. Формат TRIOMAT1

```
MAGIC(8) | hlen(4, LE) | заголовок | payload до конца файла
```

- `MAGIC = b"TRIOMAT1"`; заголовок — компактный JSON
  `{"dtype":"Float64","shape":[2,2]}`; `"order"` появляется только при `F`.
- **Вариант Б**: layout в файле не хранится, payload всегда канонический
  C-порядок логических значений — F- и C-источники дают байт-в-байт один файл.
- Типы: `Bool`(1), `Int8`(1), `Int16`(2), `Int32`(4), `Int64`(8), `UInt8`(1),
  `Float16`(2), `Float32`(4), `Float64`(8), `Float128`(16 при наличии).
- Канон float — `float.hex()`: `3.0 → 0x1.8000000000000p+1`,
  `0 → 0x0.0p+0` (отрицательный: `-0x0.0p+0`), `inf`, `nan`.

### Правила приведения

| Правило | Суть |
|---|---|
| R-INT1 | `Lossy` при `\|n\| ≥ 2⁵³−1` **включительно**; за Int64 — `Err(IntRangeOverflow)` |
| R-INT3 | неинтегральный float → `Lossy` с округлением (`1.5 → 2`); NaN/inf → Err |
| R-ERR2 | агрегация: `Err` доминирует над `Lossy`; пустой агрегат → `Err(ResourceLost)` |

Закрытый набор из 19 кодов; неизвестный код отклоняется ассертом при создании.

## 7. Ридер

`sound_reader.read_file` — 9 проверок по порядку, остановка на первой
неустранимой: непустота, рамка заголовка, здравость `hlen` (≤ 4096),
JSON-объект, известный dtype, целые неотрицательные размерности, размер
payload, байты Bool из `{0,1}`, полная декодировка. Итог — через
`aggregate` (R-ERR2).

## 8. Типовые ошибки интеграции

Раздел собран из ошибок, реально пойманных прогоном в этой истории.

**Почему Lossy начинается с 2⁵³−1 включительно, а не «после него».**
У float64 мантисса 53 бита: все целые до 2⁵³−1 представимы точно, 2⁵³ — тоже,
а вот 2⁵³+1 — уже нет. Конвенция рисует границу консервативно: всё от
2⁵³−1 и выше помечается `Lossy`. Логика: потребителю, который получит
«точное» 2⁵³−1 и тут же сконвертирует его в float с прибавлением единицы,
потеря начнётся без всякого предупреждения — флаг на границе страхует ровно
этот переход. В v0.1 стояло `>`, в v0.2 зафиксировано `>=`; проверка:
`int_check(2**53 - 1)` → `Lossy`.

**Bool валидировать по сырым байтам, до `frombuffer`.**
`np.frombuffer(..., dtype=bool)` молча превращает байт `2` в `True`. Проверка
`any(b not in (0,1))` обязана стоять **до** декодирования — иначе мусорный
байт тихо становится истиной.

**Порядок payload — всегда C (вариант Б).**
Не храните layout в payload и не пытайтесь читать F-матрицу через
`reshape(..., order="C")`: получите правильные числа в неправильных местах.
`unpack_octave` делает это сам (`order="F"` + `asfortranarray`); `copy()`
без `order="F"` тихо возвращает C-хранилище.

**Журнал: `=` только в `bind`.**
Регулярка на «каждая строка журнала содержит `=`» — ошибка: `result` и `err`
пишутся без `=`.

**Первый-ошибка-побеждает в SC.**
Порядок `SC-002 → SC-061 → SC-060` закрытый: если найдено SC-002, SC-060
не сообщается. Не ждите полного списка за один прогон.

**Целочисленное деление — усечение к нулю, не floor.**
`-3/2 → -1` (не `-2`, как дал бы Python-оператор `//`). Не вычисляйте его
через float (`int(a/b)`): на `|n| ≥ 2⁵³` float теряет единицы. Реализация в
ядре — чисто целочисленная, точна на всём Int64.

**`in` — ключевое слово.**
`wire in -> scaled ;` не парсится: `in` уходит в `kw`-токен, а не в `id`.
Называйте провода иначе (`src`, `in_sig`).

**Параметры правил — через пробел, не через запятую.**
`rule f x, y = ...` — ошибка разбора; правильно `rule f x y = ...`.

**Канон float — не изобретайте свой форматтер.**
Канон — это `float.hex()`: строчные нибблы, 13 цифр мантиссы. Собственный
форматтер неизбежно даст расхождение с этим правилом (в истории пакета был
именно такой баг — заглавные нибблы) и сломает сравнение канонов по строкам.

**Замыкание — снимок в момент обращения.**
Обращение к имени функции фиксирует окружение; поздние изменения внешних
имён замыкание не видит. Это не баг, а договорённость — но её легко
проморгать при переносе кода.

## 9. Известные ограничения

- Целые ограничены Int64; всё шире 2⁵³ честно помечается `Lossy` или `Err` —
  тихой усадки нет.
- `Float128` доступен только если поддерживает сборка numpy.
- `hlen` ограничен 4096 байтами (проверка ридера).
- Строки в канон-сериализации сохраняются дословно; экранирование внутри
  кавычек на совести автора спеки.
- Оператор `%` для отрицательных целых наследует семантику Python
  (знак делимого), а не C.
