# Инструкция по дубляжу
## версия: 1.0
## назначение: рабочий контракт для реплеера-дублёра на новой платформе
## соседние документы: spec_piano.md (0.5.1), accord.md (v1.2), sound-0.5.1 (формат журнала)

---

## 1. Кто такой дублёр

Дублёр — независимый исполнитель журнала. Один файл журнала, три и более
платформ, ноль IPC. Дублёр знает ТОЛЬКО словарь шагов журнала. Он не знает:
- foldlist и задачу трейса;
- Piano и его грамматику;
- структуру программы и исходник;
- чужие интерпретации семантики.

Дублёр НЕ является перепроверщиком структуры и отпечатка транскриптора:
дублёр-перепроверщик — это второй транскриптор, а их в цепочке быть
не должно (решение по DemoAdd). Вердикт — только по значениям шагов.

## 2. Вход

Один аргумент командной строки: путь к текстовому файлу журнала
sound-0.5.1. Дублёр читает ФАЙЛ, не память эмиттера. Первая реализация
дублёра обязана читать текстовый файл и парсить его самостоятельно —
это условие независимости (урок пересборки DemoMaze2).

## 3. Формат шага

Каждый шаг — строка вида:

    tK <op> <arg1> <arg2> ... -> <значение>

- tK — канонический номер шага, K возрастает с 1 без пропусков;
- аргументы — либо константы, либо ссылки tJ с J < K (ИНВ-Р.1:
  ссылка всегда назад; висячая ссылка — дефект, см. §6);
- значение — каноническая сериализация значения шага.
- Примечание к формату (найдено на DemoMax): в не-константных узлах
  аргументы приводятся к строковой канонической форме; узел const
  несёт значение в аргументах.

## 4. Словарь шагов (обязан знать дублёр)

core/2: const, plus, sub, mul, lt, eq, if, part, ref, set
core/3-d1: tail, len
d2-1: setv

Семантика:
- const — литерал; если const nil — создаёт хэндл пустого списка
  (начальный хэндл);
- plus/sub/mul/lt/eq — арифметика и сравнения над целыми;
- if — строгий выбор значения: обе ветви уже вычислены, узел выбирает
  одну из двух ссылок по условию (0/1);
- part E k — чтение k-й компоненты значения (кортеж/список), цена O(1)
  по семантике словаря (d2-4);
- ref H — чтение текущей версии хэндла H;
- set H V / setv H i V — запись: set — перезапись версии хэндла,
  setv — запись по индексу в пределах длины; нарушение границ индекса —
  дефект журнала (spec d2-1), не значение-ошибка;
- snoc L V — наращивание списка; tail L — хвост; len L — длина.

## 5. Семантика хэндлов (критично, примечание к sound-0.5.1)

- У хэндла есть версия. Запись (set/setv/snoc над хэндлом) порождает
  новую версию; чтение (ref) берёт текущую.
- Чтение хэндла при ОТСУТСТВУЮЩЕЙ версии: берётся начальное значение
  создающего узла (const nil — начальный хэндл пустого списка).
- Чтения хэндлов НИКОГДА не дедуплицируются (правка sound-0.5.1,
  анти-рецидив AddLong2). Дублёр не имеет права кэшировать ref-результат
  «по одинаковому значению»: хэндл и его версия — раздельные сущности.
- Дедупликация чистых узлов — дело мастера, не дублёра: дублёр исполняет
  журнал как написан, каждый шаг.

## 6. Протокол вердикта

- Значение шага не совпало с заявленным в журнале -> MISMATCH:
  номер строки, исполнено шагов, ранний выход (ИНВ-Р.2). Дальше не читать.
- Висячая ссылка или ломка нумерации -> MISMATCH с диагнозом дефекта
  журнала, до исполнения (валидация раньше вычисления, ИНВ-Р.1).
- Нарушение границ setv -> MISMATCH: это дефект журнала (дефект
  транскриптора), реплеер не обязан и не имеет права его «исполнять».
- Всё сошлось -> MATCH.

Поля отчёта дублёра (фиксированы):
    verdict: MATCH | MISMATCH
    lines_total / lines_executed
    first_error_line (при MISMATCH)
    fingerprint: <sha256 или n/a>

## 7. Отпечаток

Отпечаток — SHA-256 канонической сериализации ВСЕХ вычисленных значений
в порядке номеров шагов. Дублёр вычисляет отпечаток ПО СВОИМ значениям
и сравнивает с заявленным в шапке журнала — это мера независимости
дублёра (DemoMax: отпечаток реплеера совпал с мастерским байт-в-байт).
Дублёр НЕ перепроверяет структуру журнала и не строит отпечаток
по тексту файла — только по вычисленным значениям.

Каноническая сериализация значений:
- целое — десятичная запись;
- кортеж — (v1, v2, ...) с каноническими компонентами;
- список — [v1, v2, ...];
- err K — err:K;
- хэндл при сериализации значения — его текущая версия.

## 8. Чекпоинтинг (ENTR, accord.md секция 10)

Состояние вычислителя (ENTR-S) — таблица вычисленных значений узлов
плюс таблица хэндлов (текущая версия каждого). Управляющего состояния
нет: стека, счётчика программ помимо номера шага. Теорема состояния:
состояние на шаге k — чистая функция префикса журнала длины k-1.

Дублёр ОБЯЗАН уметь (опция --checkpoint K):
1. сериализовать состояние на шаге K в файл (формат — сериализация
   таблиц значений и хэндлов, см. §7);
2. при запуске с --resume <файл>: восстановить состояние и исполнить
   хвост журнала с шага K+1;
3. выдать тот же вердикт и ТОТ ЖЕ отпечаток, что сплошной прогон.

Приёмочный тест ENTR: рестарт с чекпоинтом обязан дать совпадение
отпечатка со сплошным реплеем байт-в-байт. Цена снапшота состояния —
O(k) по определению секции 10; дублёр волен хранить значения как угодно
(COW, общие подструктуры) — контракт на значениях, не на памяти.

Оговорка (d2-3): состояние — функция ДАННОГО журнала, не программы.
Любой инструментарий, сравнивающий состояния двух исполнений,
обязан сравнивать по журналам, не по исходникам.

## 9. Запреты (кратко)

- Не дедуплицировать чтения хэндлов. Никогда.
- Не интерпретировать семантику задачи; не «чинить» журнал.
- Не строить структурных выводов; вердикт только по значениям.
- Не читать ничего вне файла журнала (и файла состояния при --resume).
- Не пропускать исполнение strict-If ветвей: в журнале обе уже
  материализованы; выбор значения — не пропуск вычисления.

## 10. Приёмочные ворота нового дублёра

Платформа считается дублёром после прогона всех четырёх:
1. DemoAdd  — калибровка протокола, MATCH;
2. DemoMax  — независимый парсер текстового журнала, отпечаток,
   чекпоинт-рестарт (ENTR), MATCH;
3. DemoMaze2 — журнал с setv, 4602 строки, волна/P/путь, MATCH;
4. контрольные сломы (corrupt-файлы) — MISMATCH с точной локализацией
   строки и ранним выходом.

Известная платформенная ловушка: Java long — 64-битный со знаком;
на punning'е и будущих бинарных воротах — обязательный пункт сверки.
Осторожнее с целочисленным переполнением: язык его не определяет,
платформа обязана отчитаться, если журнал упирается в границы типа.
