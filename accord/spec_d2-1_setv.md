# Спецификация d2-1: операция `setv` (индексированная запись)

Версия словаря: **core/3-d2 (кандидат)**
База: core/2 (заморожен), core/3-d1 (tail, len)
Дата фиксации спеки: 2026-11-23

## 1. Форма шага журнала

```
t_k setv h i v -> <значение>
```

где:
- `h` — узел-вектор (результат `snoc`, `nil`, другого `setv` или факт-вектор);
- `i` — индекс, домен N_0, 0-нумерация (как у `part`);
- `v` — записываемое значение-узел.

Семантика: узел `t_k` — **новый вектор**, равный `h` с заменённым элементом `i` на `v`.
Старый узел `h` не изменяется и остаётся читаемым (неизменяемость значений).
Меняется только цена: пересборка вектора целиком (O(n) как у `snoc`)
заменяется точечной заменой слота — семантическая цена **O(1)**.

## 2. Границы индекса

- `0 <= i < len(h)` — обязательное условие.
- Нарушение — **дефект журнала** (формат), не значение-ошибка:
  реплеер обязан остановиться с вердиктом MISMATCH на шаге `t_k`.
  Согласуется с поведением `part` вне диапазона (дефект формата).
- Если `i` — константа, транскриптор обязан поймать нарушение статически.
  Если `i` вычисляется — проверка ложится на реплеера и валидатор.

## 3. Правила дедупликации

- Узел `setv` — **чистый**: при совпадении (h, i, v) дедуплицируется,
  значение одно и то же.
- **Хэндлы не сливаются никогда** (правка sound-0.5.1, усиливается):
  чтение хэндла после записи нельзя заменить чтением другого хэндла,
  даже если их текущие значения совпадают — история записей входит
  в смысл хэндла, доля ref/set в журналах вырастет, цена ошибки дедупликации — тоже.
- Отпечаток считается по канонической сериализации **значений**,
  не по внутреннему представлению: платформа-дублёр волен держать
  версию вектора как массив с копированием-при-записи — это её право,
  как право Octave исполнять `snoc` дёшево через `lst{end+1}`.

## 4. Объявление цены чтения (d2-4, строка реестра)

Цена `part` ранее не была объявлена — асимметрия «дёшево читать / дорого
писать» была наблюдением прогонов, а не контрактом. Фиксируется:

- **`part` — семантическая цена O(1)** в словаре core/3.
- Платформа-дублёр вправе быть умнее (массивная репрезентация),
  но не дороже: мастер считает стоимость по словарю.
- Для cons-репрезентации чтение стоило бы O(i); это расхождение репрезентаций
  закрывается тем же правилом, что цена `snoc` в Octave: цена — дело словаря,
  представление — дело платформы.

## 5. Эффект: экономика двух семей задач

| Семья | До d2-1 | После d2-1 |
|---|---|---|
| Write-sparse (счётные конвейеры, DemoRanges) | и так дёшево | без изменений |
| Write-heavy (сеточная релаксация, DemoMaze) | O(N^3), 11 181 snoc-копий | O(N^2), ожидается ~3600 копий |

`setv` не устраняет асимметрию — сужает её до алгоритмической:
платить за алгоритм, а не за носитель.

## 6. Проверка (эталон DemoMaze2)

Та же сетка 5x6, тот же вход. Обязательные метрики прогона:
- строки журнала: цель <= 1500 (было 4246);
- snoc-копий элементов: цель ~3600 (было 11 181);
- ref/set-доля: ожидаем рост с 1,2% — маркер усиленной правки sound-0.5.1;
- сходимость волны и путь — байт-в-байт с DemoMaze;
- ИНВ-Р.1: 0 нарушений ссылок.
