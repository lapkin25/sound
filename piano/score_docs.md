# SCore — реферат

версия спецификации: `sound-0.5` · 2026-11-22 · слой 2 (словарь + ANF + след)
и слой 4 (канон данных TRIOMAT)

---

## 1. Состав слоя

- **Словарь операций** — `core/2`, заморожен.
- **ANF-граф** — статическая форма программы в формате снапшота ANF/1.
- **Golden Trace** — журнал (Golden Trace) с отпечатком: динамическая форма,
  источник истины реплея.
- **TRIOMAT** — канон данных `triomat/2` (отдельный слой, описан здесь, так как
  канон живёт в каждом снапшоте).

Принципы: реплей — воспроизведение, а не доверие; сверка — hex-строками;
снапшот — платформенно-слепой.

## 2. Словарь core/2 (заморожен)

| Оп | Арность | Семантика |
|---|---|---|
| `const` | 1 | литерал-канон |

| `quotient` `mod` | 2 | усечённое деление; остаток со знаком делимого |
| `neg` `not` | 1 | унарные |
| `pow` | 2 | основание × целая степень ≥ 0 |
| `eq` `neq` `lt` `le` `gt` `ge` | 2 | полный набор сравнений, Bool-канон |

| `err` `ok` | 1–2 | тегированный канон |

### 2.1 Канонические политики арифметики

- Переполнение Int64 — по модулю 2^64.
- NaN: знак переворачивается, payload сохраняется, побеждает первый NaN-операнд.
- Денормалы — полная IEEE-семантика.

### 2.2 Черновики core/3

| Кандидат | Мотивировка |
|---|---|
| `closure` | лямбды `x \|-> body`; env-срез по ссылкам |
| `extcall` | вызов внешней библиотеки; в следе — только вход и выход |
| `tail` | отсечение головы списка: три случая подряд (лента ТМ, декремент Минского, Марков-шаг) упёрлись в его отсутствие; без него операции — O(n) через рекурсию |
| язык мер | кортежи мер + структурные меры (длина списка) для полного Аккорда |

## 3. Канон данных TRIOMAT: triomat/2

| Тип | Форма |
|---|---|
| Int64 / Float64 | 16 hex, нижний регистр |
| Bool | `true` / `false` |
| String | `s<len>:<hex-utf8>` |
| Err / Ok | `err:<tag>:<payload>` / `ok:<value>` |
| List | `N\|<len1>:<e1>,<len2>:<e2>,...` — каждый элемент с префиксом длины |
| Empty list | `0\|` |

Правила (вариант A, принят для core/2):

- `<lenK>` — длина в символах канонической строки элемента без префикса;
- скаляры внутри списка получают префикс `16:` (Int64/Float64) или `s<len>:`
  (String) — префикс элемента совпадает с формой самозакрывающейся записи;
- разбор однозначен на любой глубине вложенности; двусмысленность
  `2\|2|...` из triomat/1 устранена.

Пример:

```
{ {1, 2}, {3} }  →  2|41:2|16:0000000000000001,16:0000000000000002,21:1|16:0000000000000003
```

Проверка: внутренние элементы — 41 и 21 символ; границы восстанавливаются по
числам. Цена: списки скаляров удлинились примерно вдвое — принято осознанно
ради однозначности разбора.

Канонические политики общие с арифметикой (§ 2.1). Пример входа-вектора:

```
Events = 2|19:16:0000000000000064,19:16:0000000000000065
```

## 4. Формат снапшота ANF/1

```
# sound-anf/1
spec: Demo
sound: sound-0.5
dict: core/2
canon: triomat/2
handles: r
seed: none

--- environment ---
--- funcs ---
--- graph ---
--- journal ---

fingerprint: <64 hex>
```

Поля `dict` и `canon` связывают файл со словарём и каноном данных; реплей
отказывается парсить незнакомые версии. Поле `handles:` — перечень хэндлов,
введён для валидации `set` без исходника (критерий 5). Кодировка UTF-8, NFC,
одиночные пробелы, табуляции запрещены, `\n` в конце каждой строки и файла;
комментарий `;` — только в конце строки журнала, в отпечаток не входит;
платформенно-зависимых полей нет — снапшот платформенно-слепой.

## 5. Канонический закон нумерации

Номера `t0..tK-1` назначаются топологическим порядком; среди готовых узлов
выбирается лексикографически минимальный по строке `(op, args)`. **Дубликат
канонической строки — ошибка компиляции**: транскриптор обязан слить одинаковые
узлы (закон дедупликации; работает как CSE на этапе нумерации).

Следствия:

- журнал — подпоследовательность графа;
- один исходник — один файл байт-в-байт;
- вставка узла невозможна без перенумерации хвоста.

Ограничение: слияние чтений корректно, лишь пока между чтениями нет записи в
тот же хэндл — отсюда критерий 7б.

## 6. Отпечаток

```
fp_0 = 64 нуля (hex)
fp_i = SHA256( fp_{i-1} || UTF-8(line_i) || 0x0A )
```

Покрывает **только журнал** (любое изменение статики проходит через журнал как
`const`/`ref`/`set`). Пустой журнал → нулевой отпечаток. Журнал включает и
подследы (`fK.uM`) — они накрываются отпечатком наравне с основными строками.

## 7. Валидатор

Работает **без Piano-исходника**. Критерии:

1. полная шапка, согласованный `dict`/`canon`;
2. плотная каноническая нумерация;
3. DAG и разрешимость `ref`;
4. журнал — подпоследовательность графа; для каждого `if` исполнена одна
   согласованная ветвь;
5. `set` — только в объявленный хэндл (сверка со списком `handles:` шапки);
6. err — только по Railway;
7. отпечаток пересчитывается байт-в-байт;
   - **7а** — нет дубликатов узлов;
   - **7б** — между двумя чтениями хэндла нет его записи (первое чтение до
     записи — отказ).

## 8. Транскриптор (компилятор Piano → SCore)

Пять стадий: разбор в дерево выражений → типизация и разрешимость имён →
канонизация (точный разбор литералов через рационалы, стирание сахара,
канонизация порядка правил) → спуск в ANF с канонической нумерацией → эмиссия
снапшота ANF/1.

Обязательства: не вычислять арифметику (кроме точного разбора литералов);
один исходник — один граф и один файл байт-в-байт; ошибки компиляции не
попадают в след; эталоны корпуса — критерий приёмки: снапшот сравнивается
байт-в-байт с эталоном, расхождение — дефект снижения или нумерации.
