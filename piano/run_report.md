## 3. Две находки прогона

### 3.1. Валидатор поймал эталон: DemoMinsky, критерий 7а

Эталон DemoMinsky содержит по одному чтению счётчика `c` на каждый шаг декремента. Между последовательными чтениями стоит `set c` — значения чтений различны, слияние недопустимо. Но канонические строки этих узлов идентичны (`ref c`), а замороженный закон нумерации объявлял любой дубликат канонической строки ошибкой компиляции. То есть рукопись DemoMinsky формально нарушала собственный закон — дыра была в законе, а не в рукописи.

Симптом: валидатор отклонил эталон по 7а — «дубликат канонической строки `ref c`, узлы t6, t14, t22».

### 3.2. Сравнение поймало транскриптор: AddLong2, слияние чтений через set

Транскриптор дедуплицировал чтения хэндла переноса в AddLong2 по общему правилу «дубликат — ошибка» и слил два чтения `ref c`, между которыми стоит `set c`. Место дефекта — второй разряд числа A = {9, 1}, B = {8, 1} (перенос после первого разряда — 1):

```
эталон:        транскриптор (дефектный):
t9  ref c -> 0 ; чтение до первой записи   t9  ref c -> 0
t10 plus ...   ; 1+8+0 = 9                 t10 plus ...
t11 mod  -> 9  ; разряд 9                  t11 mod  -> 9
t12 set c -> 1 ; перенос = 1               t12 set c -> 1
t14 ref c -> 1 ; чтение нового переноса    (t14 слит с t9)
t15 plus ...   ; 1+1+1 = 3                 t15 plus ...  ; 1+1+0 = 2  <-- неверно
```

Итог: сумма {9,8}+{1,1} = 302 в неверном следе против 310 в эталоне — тихий, правдоподобный, невоспроизводимый дефект. Сравнение байт-в-байт выявило расхождение на строке t15 журнала; реплей на дублёре воспроизвёл дефектную сумму, подтвердив, что журнал вёл себя самосогласованно — ошибка была в графе.

### 3.3. Симметрия находок

Критерий 7а поймал рукопись, сравнение поймало код. Оба инструмента сработали по назначению, но вскрыли одну и ту же дыру с двух сторон: закон нумерации не различал мутабельные и немутабельные ячейки при дедупликации.

## 4. Правка закона нумерации (sound-0.5 -> sound-0.5.1)

Три пункта, минимальные по объёму:

1. **Дедупликация не применяется к чтениям хэндлов.** Повторный `ref h` всегда даёт отдельный узел, независимо от наличия `set` между точками исполнения. Причина: статический граф не обязан знать, есть ли запись между двумя чтениями в конкретном исполнении, — а слияние может оказаться неверным. Цена: несколько лишних узлов, семантика не страдает.
2. **Тай-брейк для повторяющихся канонических строк.** Единственный легальный источник повторов теперь — чтения хэндлов; среди них порядок назначается по первым употреблениям имени в Piano-исходнике (снижение слева направо). Порядок остаётся детерминированной функцией исходника.
3. **Критерий 7б переформулирован: самопоследовательность журнала.** Для каждого хэндла значение каждого `ref h` в журнале обязано равняться последнему предшествующему `set h` (или начальному значению из шапки `handles:`). Проверка выполняется без Piano-исходника. Старая формулировка (запрет записи между слияемыми чтениями) снимается как несостоятельная — она опиралась на возможность слияния, которого больше нет.

Ограничение, которое правка снимает: закон перестаёт запрещать легальные программы с многократным чтением хэндла — корпус их теперь содержит два (AddLong2, DemoMinsky).
