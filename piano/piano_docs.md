# Piano — реферат слоя 1 (язык)

Версия спецификации: **sound-0.5.1** · Статус: слой доказан на всём корпусе (проход транскриптора 15/15)

Piano — язык слоя 1 системы Sound: язык декларативных детерминированных вычислений
с принудительной остановкой и полной наблюдаемостью. Исходник Piano не исполняется
напрямую — он снижается транскриптором в граф (SCore) и исполняется рантаймом (Trio),
после чего воспроизводится дублёрами на независимых платформах по одному лишь снапшоту.

## 1. Три столпа

1. **Тотальность.** Каждая программа гарантированно завершается. Неограниченные циклы
   запрещены (нет For/While, нет μ-оператора); рекурсия допускается только с мерой
   (см. Аккорд). Каждый след конечен, отпечаток всегда определён.
2. **Детерминизм.** Один исходник (+ вход) — один граф — один журнал — один отпечаток,
   байт-в-байт, на любой платформе. Нет неопределённого порядка вычисления, нет
   зависимостей от среды, даты, рантайма.
3. **Полная наблюдаемость.** Журнал описывает всё, что случилось: каждое чтение,
   каждая запись, каждый шаг складывания. Ничего не «проглатывается».

## 2. Декларации

| Декларация | Смысл | Мутабельность |
|---|---|---|
| `fact name = expr` | факт: значение фиксируется при инициализации | нет |
| `param name :: T` | параметр: значение подаётся при запуске, снижается в `environment` | нет |
| `handle name = expr` | хэндл: именованная изменяемая ячейка | да (`set`) |
| `rule name[args] := body` | правило: определение функции | — |

## 3. Типы

Аннотация типа — обязательство вида `:: T`: `_Int64`, `_Float64`, `_List[T]`,
`_Vector[T, N]`, `_Hand[T]`. Типы не вычисляются и не порождают собственной
арифметики; значения живут в каноне TRIOMAT. Несоответствие аннотации —
ошибка компиляции, в след не попадающая. `Stream` зарезервирован, семантика
не определена (разрабатывать только под схему «батч как снапшот»).

## 4. Правила и Аккорд

Правило — определение функции; рекурсивное правило обязано нести меру:

```
rule addRec[a_, b_, c_, n_] @terminates[n] :=
    If[n == 0, ..., addRec[..., n - 1]]
```

Аккорд (полная версия, язык мер v1):

- **Мера** — выражение из ограниченного языка: параметры правила, без вызовов правил;
  домены — Int64 >= 0 и длина списка `len[p]`. Оба well-founded.
- **Строгое убывание** на каждом рекурсивном ребре (R1), домены well-founded (R2),
  структурная мера `len` (R3), перенос ограничений из гварда ветки — R4 (черновик),
  лексикографический кортеж 2–4 компонент (R5).
- Мера — статическое знание: не создаёт узлов и не входит в отпечаток.
- Проваленное обязательство — ошибка компиляции; снапшот не выдаётся.

## 5. Таблица снижения (набросок v0.5)

| Piano | Узел/снижение | Комментарий |
|---|---|---|
| `a + b` | `plus` | политика арифметики — словарь |
| `a * b` | `mul` | — |
| `If[c, x, y]` | оба ветви в графе | граф отвечает «что может случиться» |
| `ref h` / `set h e` / `wire e -> h` | чтение/запись хэндла | запись — синтаксический сахар |
| `foldlist[f, z, xs]` / `fold2[f, z, xs, ys]` | примитивная рекурсия в канонической форме | подследы — в журнал |
| `part[xs, i]` | элемент списка | динамическая проверка `err:bounds` |
| `snoc[xs, x]` | добавление в конец | O(n) по построению |

## 6. Railway

Грань «статическое / динамическое» проводится для каждой операции осознанно:
что доказуемо статически (разрешимость имён, согласованность аннотаций,
статические длины для `fold2`, меры Аккорда) — не должно проверяться в следе;
что проверяется только на данных (`err:bounds`, `err:lenmismatch`, деление на ноль)
— остаётся рантайм-страховкой. Проваленная статическая проверка не может
«случиться в рантайме», и наоборот — динамическая не выносится наверх без оснований.

## 7. Вход как снапшот (param)

Данные никогда не приходят «в рантайме» — они замораживаются в снапшот транскриптором.
Запуск = подача значений параметрам; снижение — в секцию `environment` канона TRIOMAT.

Правила П1–П6 (зафиксировано):

| № | Правило |
|---|---|
| П1 | Честный литерал: точный разбор рационалов `m/10^e`, зеркальный тест hex<->decimal |
| П2 | Проверка аннотации против TRIOMAT/2; несоответствие — отказ запуска |
| П3 | Связывание размерности: литеральное `N` сверяется, символическое связывается структурно и становится статическим знанием (без узлов и отпечатка) |
| П4 | Размещение: единственная строка в `environment`, чтение только узлом `ref` |
| П5 | Иммутабельность: `set`/`wire` в параметр запрещены; чтения сливаются как у фактов |
| П6 | Неиспользуемость: непрочитанный параметр легален; отпечаток покрывает только журнал |

Следствие: **граф инвариантен к входу** — один исходник при разных входах даёт
один и тот же граф байт-в-байт. Эволюция состояния — цепочка снапшотов: выход
шага k подаётся фактом в шаг k+1.

## 8. Границы выразительности

- Sound — строгий фрагмент машины Тьюринга: тотальные, детерминированные,
  с принудительной остановкой. Не расширяет класс вычислимого — расширяет
  класс **проверяемого**.
- Классические модели: Марков (шаг изоморфен, двигатель — руками через `foldlist`),
  рекурсивные функции (почти дословно; μ-оператор отсутствует намеренно),
  ТМ/Пост/Минский (встраиваются, только останавливающиеся прогоны; счётчики —
  унарные списки, Int64 не годится из-за арифметики по модулю 2^64).
- ТСП за полином: «Sound не решает за полином» эквивалентно P != NP с оговоркой
  про выразительность языка мер; экспоненциальные методы (Хелд–Карп) выразимы.

## 9. Глоссарий

- **Граф вычислений** — статическая форма программы после спуска в ANF: DAG узлов
  `t0..tK-1`, каждый — операция словаря ядра со ссылками на предшественников.
  Зафиксированы обе ветви каждого `If`, все чтения хэндлов, канонический порядок.
  Граф — семантика *программы*; его динамический двойник — журнал (семантика *экземпляра*).
- **Хэндл** — именованная изменяемая ячейка (`handle h = e`), единственный канал
  императивности. Чтение — `ref h`, запись — `set h te`. Записи делают мутацию
  наблюдаемой; циклы через хэндлы запрещены — граф остаётся DAG'ом.
- **Ячейка** — единица хранения значения: немутабельная (факт, параметр — чтения
  сливаются) и мутабельная (хэндл — чтения не сливаются, между ними может быть запись).
- **Аннотация типа** — обязательство `:: T`, проверяемое статически на типизации;
  ограничивает паттерны правил; несоответствие — ошибка компиляции.
- **Статическая проверка** — утверждение о программе, проверяемое без исполнения.
  Противоположность — динамические проверки словаря (`err:bounds`, `err:lenmismatch`).
- **Реплей** — исполнение снапшота ANF/1 рантаймом-дублёром без Piano-исходника:
  вычеркнуть неисполненное, вычислить каждый узел собственной арифметикой,
  сверить hex-строками с записанным. Не интерпретирует язык — сжат до арифметики словаря.
- **Транскриптор** — компилятор Piano -> SCore, пять стадий: разбор, типизация,
  канонизация, спуск в ANF с канонической нумерацией, эмиссия снапшота ANF/1.
  Ключевое обязательство: **не вычисляет арифметику** (кроме точного разбора
  литералов) — раскладывает, а не исполняет.
- **Дедупликация** (правка sound-0.5.1) — слияние узлов с одинаковой канонической
  строкой `(op, args)` в один узел: одна строка в графе означает одно значение в любом
  исполнении. Применима к чистым узлам и чтениям немутабельных ячеек. **Чтения хэндлов
  никогда не дедуплицируются** — повторный `ref h` всегда отдельный узел: статический
  граф не знает, встретится ли запись между двумя чтениями в конкретном исполнении.
  Повтор, который не слился (и не является чтением хэндла), — ошибка компиляции;
  порядок повторов определяется первыми употреблениями имени в Piano-исходнике.
- **Аккорд** — свод обязательств по завершимости рекурсивных правил; делает остановку
  принудительной. Подробно — accord.md.
