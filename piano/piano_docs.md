# Piano — реферат

версия спецификации: `sound-0.5` · 2026-11-22 · слой 1 архитектуры Sound

---

## 1. Назначение и место в архитектуре

Piano — нотация для людей. Язык **не исполняет** программы — он их *раскладывает*:
транскриптор переводит исходник Piano в снапшот формата ANF/1 слоя SCore, после
чего исходник и компилятор больше не нужны: снапшот валидируется сам по себе и
реплеится дублёрами Trio сам по себе.

```
Piano (слой 1)      — нотация; не исполняет, раскладывает
   │ транскриптор: разбор → типизация → канонизация → спуск в ANF → снапшот
SCore (слой 2)      — словарь операций (core/2) + ANF-граф + Golden Trace
   │
Trio (слой 3)       — рантаймы-дублёры; реплей журнала, сверка hex-строками
   │
TRIOMAT (слой 4)    — канон данных; текущая версия triomat/2
```

Принципы слоя:

- Piano не исполняет — раскладывает.
- Компилятор не вычисляет арифметику (кроме точного разбора литералов).
- Всё запрещённое в Piano просто не доходит до словаря.
- Один исходник — один граф и один файл байт-в-байт, на любой платформе.

## 2. Три столпа

1. **Всё — выражение.** Декларации, правила, хэндлы — выражения с головами;
   statement'ов нет.
2. **Вычисление — развёртка правил.** Семантику задают правила переписывания,
   а не операторы.
3. **Императивность — только через хэндлы.** Мутация видима в графе и в журнале.

## 3. Декларации

| Декларация | Семантика |
|---|---|
| `fact a = e` / `fact a :: T = e` | вычисляется при инициализации; значение фиксируется навсегда |
| `rule f[p_] := e` | отложенное; нерекурсивные — inline, рекурсивные — в `funcs` |
| `wire e -> h [keep\|update\|flush]` | единственный путь записи в хэндл |
| `handle h = e` | изменяемая ячейка; чтение — `ref`, запись — `set` |
| `param p :: T` | вход; подстановка до компиляции (§ 9) |
| `invariant e` | зарезервировано; семантика не утверждена |
| `extern f :: T @lib` | черновик core/3; в следе — только вход и выход |
| `import M` | раскрытие имён на стадии типизации; в снапшот попадают имена |

Грамматика параметра: `param_decl ::= "param" IDENT ["::" type]`.
Значения по умолчанию запрещены — они стёрли бы грань «семья программ / экземпляр».
Коллизия имени параметра с фактом, хэндлом или правилом — ошибка компиляции.

## 4. Типы и аннотации

Типы: `_Int64`, `_Float64`, `_Bool`, `_String`, `_Matrix[T, dims]`,
`_Vector[T, dim]`, `_Stream[T]`, `_Result[ok, err]`.

Типы — аннотации и статические проверки; собственной арифметики у типов нет.
Аннотация — это обязательство: значение соответствует канону объявленного типа
в TRIOMAT. Несоответствие — ошибка компиляции, в след не попадает. Аннотации
также ограничивают паттерны правил (`acc_Int64`).

`_Stream[T]` зарезервирован без семантики; его осмысленная разработка — только
под схему «батч как снапшот» (§ 9), не как «живой канал».

## 5. Правила

- Паттерны — только синтаксические (`_`, `x_Integer`); условия `x_ /; cond`
  запрещены и переносятся в тело как `If`.
- Порядок правил канонизируется: лексикографический по паттернам либо явный `@n`;
  порядок в файле смысла не несёт.
- Имена ядра не переопределяются.
- Рекурсия — только с `@terminates[мера]` до v1.0 (см. § 5.1).
- `fold2[f, init, L1, L2]`: равенство длин проверяется статически, когда длины
  известны компилятору (литералы или связанное параметром `N`); иначе — узловая
  проверка с `err:lenmismatch` до первого шага.

### 5.1 Аккорд: обязательства завершимости

Рекурсия без ограничителя — единственный легальный способ «крутиться вечно»,
поэтому она разрешена только с доказательством остановки на этапе компиляции.
Метафора имени: рекурсивные рёбра правила — струны; аккорд звучит, только когда
*все* струны убывают согласованно.

| Обязательство | Содержание |
|---|---|
| Мера | Выражение из ограниченного языка: только параметры правила, без вызовов правил; значение — из well-founded домена (Int64 ≥ 0; в проекте — длина списка) |
| Строгое убывание | На каждом рекурсивном вызове мера аргументов вызова строго меньше меры текущих аргументов — для каждого ребра рекурсии |
| Лексикографическая пара | Для взаимной и структурной рекурсии — мера-кортеж `(m1, m2, ...)` с лексикографическим убыванием |
| Статическая проверка | Обязательства разбирает транскриптор: простые арифметические соотношения; не доказал — ошибка компиляции, в след не попадает |

Примеры из корпуса — все прошли через Аккорд:

```
rule addRec[a_, b_, c_, n_] @terminates[n] :=      ; n убывает на 1
    If[n == 0, ..., addRec[..., n - 1]]

rule toQ[n_] @terminates[n] :=                     ; n делится нацело вниз
    If[n < Q, {n}, snoc[toQ[quotient[n, Q]], mod[n, Q]]]

rule step[st_, l_, r_] @terminates[steps] :=       ; steps убывает
    If[st == Halt, ..., step[..., steps - 1]]
```

Из Аккорда следует всё обещанное про след: рекурсия не может зациклиться,
каждый подслед конечен, журнал конечен, отпечаток определён.

Родословная: классическая индукция по well-founded порядку; на практике — приём
termination-checker'ов Agda и Coq. Отличия: доказательство обязательно (язык не
позволяет записать рекурсию без меры), а цена провала — не «программа может
висеть», а «снапшот не будет выдан».

Статус: работает **фрагмент** — одна мера-выражение над Int64. Полный Аккорд
требует языка мер с кортежами и структурными мерами (длина списка) — черновик
core/3; без него не выразить Аккорд для машины Минского и чистого шага Маркова.

## 6. Запрещённое

- `For` / `While`, `Goto`, `Break`, `Module` / `Block`.
- Сайд-эффекты вне хэндлов.
- Неограниченный поиск (μ-оператор) — запрещён по дизайну.
- Случайность — только детерминированный генератор по сиду.
- Повторение — `foldlist` / `fold2` или рекурсивное правило.

## 7. Ошибки: Railway

`Err[tag, payload]` и `Ok[v]` — конструкторы значений.

- Err протекает через арифметику неизменным.
- `if` с err-условием возвращает err без исполнения ветвей.
- В журнал попадают только исполненные узлы.

Пример из DemoDiv0: `err:div0:3ff0000000000000` — тегированный канон, ветвь
`else` остаётся только в графе, в журнале её нет.

## 8. Таблица снижения

| Конструкция | Узлы | Гарантия |
|---|---|---|
| Литерал Float | `const <hex>` | точный разбор рационалов `m/10^e`, ties-to-even; `strtod` хоста запрещён |
| Литерал Int | `const <hex>` | допкод 2^64; выход за Int64 — ошибка компиляции |
| `a + b` и прочий инфикс | `plus/sub/mul/div/eq/...` | сахар стёрт; приоритеты — фиксированная таблица (до grammar-freeze) |
| `x` | `ref x` | переменная и хэндл — один узел |
| `If[c, a, b]` | `eq` → `if` → ветви | в графе обе ветви, в журнале — исполненная |
| `{a, b, c}` | `list` | вычисление слева направо |
| `m[[i, j]]` | `part` | индексы Int64; выход за границы — `err:bounds` |
| `f[a, b]` | inline / `apply` | детерминированный выбор; рекурсия — `apply` |
| `foldlist[f, i, L]` | `foldlist` | лево-ассоциативно |
| `fold2[f, i, L1, L2]` | `fold2` | проверка длин на узле до первого шага; при известных длинах — статически |
| `snoc[L, v]` | `snoc` | дописывание в хвост; канонически — полная перезапись |
| `x \|-> body` | `closure` | черновик core/3; env-срез по ссылкам |
| `wire e -> h` | `set h te` | единственная точка мутации |

## 9. Ввод данных: `param` и схема «вход как снапшот»

Проблема: ввода-вывода в Piano нет, а реплей обязан работать по одному снапшоту.
Если данные поступают извне во время исполнения, след не покрывает место, где
живёт недетерминизм. Решение — сместить вход на более ранний слой: данные
замораживаются в снапшот ещё транскриптором.

```
внешний мир (оболочка)
   │  поставляет данные ДО компиляции
   ▼
транскриптор: программа + данные → один снапшот ANF/1
   │
   ▼
дублёры реплеят снапшот — им больше ничего не нужно
```

Запуск = подача значений параметрам в точном текстовом виде, по одному на
параметр. Значения попадают в секцию `--- environment ---` в каноне TRIOMAT/2;
чтение — только узлом `ref`.

Правила снижения (зафиксированы):

| № | Правило | Содержание |
|---|---|---|
| П1 | Честный литерал | значение парсится тем же точным разбором рационалов `m/10^e`, что и литералы исходника; `strtod` хоста запрещён; зеркальный тест hex ↔ decimal обязателен |
| П2 | Проверка аннотации | канон значения сверяется с объявленным типом против TRIOMAT/2; несоответствие — отказ запуска |
| П3 | Связывание размерности | литеральное `N` сверяется с фактической длиной; символическое `N` связывается структурно — длиной поданного списка — и становится статическим знанием: участвует в статических проверках, но не создаёт узлов и не входит в отпечаток |
| П4 | Размещение | значение — единственной строкой в `environment`, имя = имя параметра; чтение — только `ref` |
| П5 | Иммутабельность | `set`/`wire` в параметр запрещены; валидатор отсекает: цель `set` обязана значиться в списке хэндлов шапки |
| П6 | Неиспользуемость | непрочитанный параметр легален; значение попадает в след только через чтение |

Следствия схемы:

- **Граф инвариантен к входу.** Значение параметра — не узел, а запись
  окружения: один исходник при разных входах даёт один и тот же граф
  байт-в-байт, различаются только `environment` и журнал. Вход не участвует
  в нумерации никогда.
- **Оболочка — арбитр.** Порядок событий, дедупликация, тайминги — всё
  недетерминированное решает внешний мир до входа в детерминированное ядро.
- **Эволюция состояния — цепочка снапшотов.** Снапшот № k вычисляет новое
  состояние, оно подаётся как факт в снапшот № k+1; вся история —
  верифицируемая цепочка следов.
- **Грань «программа / данные» стирается внутри слоя.** Спецификация Piano —
  семья программ; снапшот — конкретный экземпляр, прошитый данными.

Цены честно: нет инкрементальности (новое событие — пересборка снапшота);
вход живёт в файле (большие данные — задача не того слоя).

## 10. Границы выразительности

- Sound — тотальная, детерминированная система с принудительной остановкой:
  `Sound ⊊ частично-рекурсивные`, `Sound ⊆ тотально вычислимые`. Полнота
  Аккорда ограничена выразительностью языка мер — это предел дизайна, а не баг.
- **Классические модели встраиваются, но не равноправно** (останавливающаяся
  часть каждой): нормальные алгорифмы Маркова — почти изоморфизм шага
  переписывания, но двигатель цикла — руками (`foldlist`); рекурсивные функции —
  почти дословно (`foldlist` = примитивная рекурсия); машина Тьюринга и Поста —
  через два списка и рекурсию по состоянию; машина Минского — счётчики нельзя
  держать в Int64 (арифметика по модулю 2^64), только унарные списки.
- Встраивается только останавливающийся прогон; зато журнал Sound — полная
  история вычисления ТМ, воспроизводимая байт-в-байт.
- Утверждение «на Sound нельзя решить задачу коммивояжёра за полином» — в
  точности эквивалент проблемы P ≠ NP (с оговоркой про выразительность мер);
  тотальность не ограничивает сложность — экспоненциальный перебор выразим
  прямо сейчас.
