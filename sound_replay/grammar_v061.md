===============================================================
0. Канонический образ программы
===============================================================

Канонический образ программы — линейный след SSA-узлов (журнал):

  tXXXX op arg1 arg2 -> значение ; комментарий

Каждый шаг — одна операция словаря. Управляющие конструкции (if, foldlist,
while) — поверхностные формы: компилируются в журнал статической развёрткой
и в журнале отдельных узлов не оставляют.

Инвариант: структура журнала зашита в исходник; данные-зависимым может быть
только ЧИСЛО шагов (ступень 1: foldlist по вычисленному списку; ступень 2:
bounded while), но не их структура.

===============================================================
1. Словарь v0.6 (заморожен с demo_mulsq)
===============================================================

Атомарные операции фиксированной семантики — полный список:

  const c            -> скалярный литерал или nil (пустой список)
  plus a b           -> a + b          (целые)
  mul a b            -> a * b          (v0.6; переход через линию разрешимости)
  lt a b             -> 1, если a < b; иначе 0
  div a b            -> floor(a / b), b >= 1
  mod a b            -> a - b*floor(a/b), b >= 1
  len a              -> длина списка
  snoc a b           -> список a с элементом b в конце
  tail a             -> список a без первого элемента
  part a i           -> i-й элемент списка a (0-индексация)
  if c a b           -> значение a при c != 0, иначе b

Пояснения канона:
  - Разность выражается через плюс с отрицательной константой
    (const -1, plus). Отдельной операции нет — принцип минимальности
    (переформулирован при заморозке v0.6): словарь = атомарные операции
    фиксированной семантики, а не "всё выводимо из остального";
    при том требовании словарь пуст — plus сам ни из чего не выводим.
  - eq выражается двумя lt + двумя if (см. demo_digsum t0046-t0049);
    отдельной операции нет.
  - div и mod — "широкие" операции: внутри одного канонического шага
    совершают до b шагов работы (вычитание до исчерпания). Журнал этого
    не показывает. Скрытые циклы — свойство словаря с первого дня,
    осознано при разборе вопроса "while через divmod".

Иллюзии реестра (не забыть):
  - div/mod были "широкими" с первого дня; делители-константы маскировали это.
  - foldlist по вычисленному списку = данные-зависимая длина шагов,
    присутствовала до легализации ступени 1; маскировалась статическими
    списками-заготовками.

===============================================================
3. Оператор if — семантика развёртки
===============================================================

  if C then A else B  ≡  узел if(C, A, B) — один канонический шаг.

Компилятор вычисляет C; вычисляется только выбранная ветвь.
В журнале: узлы невыбранной ветви не появляются. Стражи if-условий —
легально мёртвые узлы, если их значение не потребляется выбором.

===============================================================
4. foldlist — семантика развёртки (ступень 1, легализована demo_mulsq)
===============================================================

  foldlist f acc L  ≡  последовательное применение f к acc и элементам L.

Развертка журнала:
  - по элементам: страж len > 0, part L 0, шаг свёртки, tail L;
  - инвариант потребления: L укорачивается за итерацию (tail-цепочка);
  - источник итераций — данные-список; Л легален вычисленным
    (первый эталон с этим — demo_mulsq, список digits);
  - граница — структурная: длина списка конечна по построению.
    Аргумент границы в протоколе: строгое убывание len по tail-цепочке.

===============================================================
5. while — семантика развёртки (ступень 2; FROZEN v0.6.1)
===============================================================

5.1. Поверхностная форма:

  while C do B end bound E

5.2. Рекурсивное определение (не в журнале; компилятор разворачивает):

  while C do B end  ≡  if C then (B; while C do B end) else ()

В журнал попадает ровно столько итераций, сколько выполнилось;
каждая итерация — операции канона, комментарии "; итерация k".

5.3. Операционная семантика:

  - Цикл с предусловием: C проверяется ДО каждой итерации.
    Ноль итераций легален; журнал содержит только вычисление C.
  - Состояние цикла — кортеж переменных, которые тело переопределяет.
    Мутация имитируется именами; по канону каждая итерация получает
    свежие узлы (SSA: x_1, x_2, ...).
  - Значение цикла — конечные значения переменных состояния после
    последней итерации (или входные при нуле итераций). Алиасы out:
    финальные значения состояния объявляются наружу напрямую.
  - Побочных эффектов нет. Всё функционально. out внутри тела запрещён
    (множественная эмиссия на неопределённом числе итераций).
  - Вложенные while легальны; глубина помечается комментариями.

5.4. Ограничение на условие (ужесточение v0.6.1):

  C обязан быть формой lt a b либо if-деревом над такими
  (канонически булево). Это каркас аргумента терминации:
  lt против монотонной меры.

5.5. Граница bound E (FROZEN: вариант Б):

  - E — выражение словаря, вычислимое БЕЗ while.
    Язык границ заморожен в варианте Б: только выражения словаря,
    вложенный while в границе ЗАПРЕЩЁН (вариант А — кандидат v0.7,
    переключение требует арбитража; пункт F-3.2 реестра).
  - Свободные переменные E не входят в множество переопределяемых телом
    (иначе граница сама циклится). E вычисляется НА ВХОДЕ в цикл.
  - bound обязателен синтаксически. Unbounded while не входит в грамматику:
    полная по Тьюрингу форма — отдельный виток с решением арбитра.
  - Семантика границы — КОНТРАКТ ПРОВЕРКИ, не оператор: компилятор НЕ
    останавливает программу по достижении E. Отношение согласия:
      фактические итерации <= value(E на входе).
    Нарушение — ошибка верификации (неверна граница либо компилятор),
    не ошибка исполнения. Прецедент нарушения пока отсутствует.

5.6. Стражи-свидетели (уточнение из demo_digsum):

  - Страж итерации (узел lt условия) вычисляется в журнале и телом
    не потребляется. Статус: легально мёртвый узел с пометкой
    "; страж, итерация k".
  - Контракт компилятора: развёртка продолжается при страже = 1,
    останавливается при страже = 0. Журнал хранит значения стражей
    как проверяемый след соблюдения контракта.
  - Выходной страж (последний, значение 0) — отдельная пометка.
  - len-узлы, потребляемые стражами, свидетелями НЕ являются.

5.7. Артефакт развёртки (уточнение из demo_decbits):

  - Обновление тела на последнем обороте, не потреблённое никем, —
    легально мёртвый узел класса "артефакт развёртки" с пометкой.
  - Причина: тело обязано вычислить все свои шаги до проверки выхода;
    на финальном обороте часть обновлений состояния не доживает
    до потребителя.
  - Профилактика (не требование): если страж висит на переменной,
    которую тело обновляет последней, артефакта не возникает
    (demo_digsum: страж на x, обновляемом последним).

5.8. Потребляемый out (уточнение из demo_decbits):

  out снимает ОБЯЗАННОСТЬ потребления узла, но не ЗАПРЕЩАЕТ его.
  Результат может быть промежуточным (t0040 bits в demo_decbits —
  одновременно результат и вход цикла 2).

5.9. Отличие от foldlist:

  foldlist: потребление элемента за шаг; граница структурная.
  while:    ничего не потребляет; граница дедуктивная (мера убывает).
  Класс обоих — PR (LOOP-уровень, Мейер-Ричи); различие — каркас
  терминации, не выразимость шагов.

===============================================================
6. Компиляция и проверка
===============================================================

  parse .sound -> AST
  compile AST  -> журнал (статическая развёртка всех поверхностных форм)
  replay журнал -> пошаговая проверка: значения, SSA, потребление,
                   стражи-свидетели, артефакты, границы

Реплеер не меняет журнал: он его проверяет. Реплей разворачивает цикл
как линейный след — метки глубины только в комментариях, для читаемости.

===============================================================
8. Ограничения v0.6.1 (сознательные)
===============================================================

  - Нет break/continue: выход только через условие
    (сохраняет while == if-рекурсию как точное определение).
  - Нет while как выражения: цикл — оператор-образная форма,
    значений не производит, только переопределяет состояние.
  - Нет unbounded while: bound обязателен.
  - Нет рекурсии с per-case терминацией: отдельный виток за заморозкой;
    кандидат v0.7.
  - Нет вложенных функций/кадров: журнал — плоский; глубина только
    в комментариях.
