# Словарный контракт (Sound / Piano)
Версия: 1.0 · Статус: frozen core / registry d2 · Дата: 2026-11-23

## 1. Назначение

Этот документ фиксирует единый интерфейс между словарём (Ур. 1) и его двумя
потребителями: транскриптором (строит журнал) и дублёром (исполняет журнал).
До сих пор интерфейс держался по факту кейсов; настоящим документом он объявлен
контрактом. Приёмочные основания: парсер Piano обязан порождать шаги только
по реестру этого документа; ворота Octave/Java сверяются только с этим реестром.

## 2. Замкнутость словаря

2.1. Каждый шаг журнала обязан быть инстансом операции, объявленной в разделе 4.
2.2. Шаг вне реестра — дефект транскриптора; реплеер обязан остановиться (ИНВ-Р.2).
2.3. Расширение словаря — только через реестр d2: заявка → спецификация →
     эксплуатация → контрольный слом → фиксация цены. Молчаливое расширение
     запрещено.

## 3. Форма шага (канон записи)

3.1. Формат строки журнала: `t<N> OP ARGLIST -> RESULT`.
3.2. Все аргументы — ссылки `tK` на ранее вычисленные узлы либо литералы в
     канонической форме. Числовые литералы: `tK`-форма для констант.
     Дефект эмиттера DemoMax (аргументы числами) — дефект нарушения канона.
3.3. Нумерация шагов каноническая, сквозная; ссылки строго назад (ИНВ-Р.1).

## 4. Реестр операций

Формат: имя · форма шага · семантика · цена · примечание.

### Core/2 (заморожено)

- `const K` · `tK const -> K` · создаёт значение K · O(1) ·
  особый случай `const nil` — создаёт начальный хэндл пустого списка (см. §5).
- `part h i` · чтение компоненты по индексу · O(1) · цена зафиксирована d2-4;
  чтение над *значением*, не над хэндлом — дедуплицируется как чистый узел.
- `snoc h v` · добавление в конец списка · O(n) · цена зафиксирована (accord §8);
  создаёт новую версию хэндла.
- `plus a b`, `lt a b`, `eq a b` · арифметика/сравнение · O(1) · переполнение —
  по платформенному контракту (Java long: сверка обязательна на воротах).
- `if c a b` · выбор значения ветви · O(1) · обе ветви вычислены до шага
  (strict-If); шаг выбирает значение, а не порядок вычисления.

### Core/3-d1

- `len h` · длина списка · семантика: длина значения; контрактная цена O(n)
  для cons-репрезентации, O(1) для массивной — цена платформенная, дублёр
  волен выбирать репрезентацию, контракт только на значениях.
- `tail h` · хвост списка · O(n) (accord §8); создаёт новую версию хэндла.

### Реестр d2 (статусы — по d2_candidates.md)

- `ref D` · чтение текущей версии хэндла D · O(1) · чтения хэндлов
  НЕ дедуплицируются (sound-0.5.1) — обязательство дублёра, не оптимизация.
- `setv D i v` · запись компоненты по индексу · O(1) · d2-1 закрыта;
  выход за границы — дефект журнала (не значение-ошибка); реплеер обязан
  остановиться.

### Формы программы (не операции словаря)

- `foldlist` — конструкция транскрипции, разворачивается в цепочку шагов;
  в журнал не попадает как отдельный шаг.
- `bind` — сахар транскрипции с ленивым раскрытием (grammar_freeze_v1);
  в журнал не попадает вовсе.

## 5. Семантика хэндлов (критично)

5.1. Хэндл — раздельная сущность состояния: имя и текущая версия (ENTR, §10).
5.2. `const nil` создаёт начальный хэндл пустого списка.
5.3. Чтение хэндла берёт текущую версию; при её отсутствии — начальное
     значение создающего узла.
5.4. Слияние состояний по «одинаковому значению» запрещено: хэндл и версия —
     не значения, дедупликации не подлежат.
5.5. Пп. 5.2–5.4 выведены из дефектов прогонов (DemoMax, DemoMaze2) и
     являются контрактом, а не фольклором реализации.

## 6. Обязательства транскриптора

6.1. Замкнутость: порождать шаги только из реестра §4.
6.2. Канон формы: аргументы в `tK`-форме, каноническая нумерация, ссылки назад.
6.3. Цены — обязательства проектирования: транскриптор вправе закладываться
     на заявленные цены (например, part = O(1)); фактические цены сверяются
     метриками (методология d2-5).
6.4. Различение хэндла и значения: транскриптор обязан различать ref-чтения
     (не дедуплицируются) и part-чтения (дедуплицируются) в самом журнале.
6.5. Эталонная сверка с независимым расчётом семантики — контур 3 приёмки,
     обязательна (урок самосогласованного дефекта DemoMaze2).

## 7. Обязательства дублёра

7.1. Буквальное исполнение: дублёр исполняет ровно реестр §4, ничего не
     домысливает; знание операции «из контекста» — дефект.
7.2. Вход — только текстовый файл журнала; собственный парсер формата (§3).
7.3. Отпечаток — дублёр обязан считать по своим вычисленным значениям
     и сверять с шапкой журнала (мера независимости).
7.4. Запрет кэширования ref-результатов «по одинаковому значению» (§5.4).
7.5. Чекпоинтинг — право дублёра (ENTR §10): состояние сериализуемо,
     рестарт обязан дать совпадающий отпечаток.

## 8. Две категории ошибок

8.1. `err K` — честное значение помеченного типа; реплеер обязан исполнять.
8.2. Дефект журнала (нарушение §3, §5, выхода setv, ссылки вперёд) —
     реплеер обязан остановиться с точной локализацией строки.
8.3. Смешение категорий (ошибка-как-значение при дефекте и наоборот) —
     дефект транскриптора (формализовано по DemoRanges / d2-1).

## 9. Изменение контракта

Документ меняется только вместе с реестром d2 или grammar-freeze; каждый
шаг изменения сопровождается кейсом-эксплуатацией и отпечатком журнала.
