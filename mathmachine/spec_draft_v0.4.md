# Спека MMP (Math Machine Project), v0.4 — драфт

Статус: черновик для сверки. Реализовано: машина sound-v0.3, компилятор v0.4.0 (лифтинг),
инварианты, факт-ряд из 6 строк. Черновые разделы: MM-4 (mu), MM-5 (Хоар), MM-EXP
(выразимость/неразрешимость), tmsim.

## 0. Метод проекта

1. Каждое утверждение подтверждается живым протоколом; строка факт-ряда закрывается
   пометкой «предсказано» только если прогноз выведен из модели **до** прогона.
2. Прогноз обязан пересчитываться от программы, а не копироваться от соседней строки
   (урок №4 журнала; сработал и на us, и на me — mul8-осечка в репетиции).
3. Совпадение на неразличающих случаях — не подтверждение (урок №1).
4. Молчаливые этапы запрещены (§5.2).
5. Две дороги вычисления — прямой вычислитель (семантика исходника) и машинный
   (исполнитель байткода) — обязаны сходиться в value; расхождение = дефект дороги.
6. Репетиция в контейнере обязательна перед выдачей патчей и прогнозов: ошибки
   обещанных программ ловятся до живого прогона.

## 2. Машина sound-v0.3

Формат: `sound.json` (fmt=sound-v0.3, src_sha256, поле slots в каждой функции).
Опкоды: `LOAD i`, `STORE i`, `PUSH c`, `ADD`, `SUB`, `MUL`, `JZ t`, `JMP t`,
`CALL [fn, nargs]`, `RET`, `HALT`.

**Контракт args по опкодам** (выведен из протоколов fact/add/mul6/mul8/mul6x8):
- `CALL [fn, nargs]` — args = список аргументов нового фрейма;
- `RET` — args=None; значение уходит через V;
- `JZ t` — единственный опкод, где args — данные перехода, а не значения;
- арифметика — args=None; результат в V.

## 3. Модель памяти

**1. Слоты фрейма (locals).** Каждый CALL создаёт фрейм: мутабельный список,
размер фиксируется компилятором (поле slots). Аргументы копируются в первые
слоты, дальше — temporaries (N, C, ACC у prec). LOAD/STORE работают только с
текущим фреймом. RET уничтожает фрейм.

**2. Стек операндов.** Один общий, сквозной через фреймы. PUSH кладёт;
ADD/SUB/MUL снимают два, кладут результат; CALL снимает nargs аргументов в слоты
нового фрейма. Между итерациями prec он пуст. *Открытый вопрос: стек не
изолирован по фреймам — альтернативная машина со стеком-в-фрейме остаётся
вариантом дизайна, не necessity.*

**3. Регистр V.** Результат последнего такта; идёт в протокол (поле state).
Единственный канал возврата значения: RET передаёт V в фрейм вызвавшего.

Служебное: pc, стек фреймов с адресами возврата, монотонный cid (парность
CALL/RET).

**Ключевой инвариант:** долговременное состояние живёт только в слотах; отсюда
три temporary-слота prec (счётчик, граница, аккумулятор).

**Программа как код-сегмент.** Программа — единый глобальный массив инструкций,
неизменяемый во время исполнения, вне стека. Фрейм не содержит кода — только
число-адрес возврата. Все живые фреймы ссылаются на один массив; CALL разрешает
функцию по имени через таблицу fns. Код не адресуем и не мутируем: STORE пишет
только в слоты, инструкции не изменяются, новых инструкций не появляется.
Гарвардская архитектура в миниатюре — и условие верифицируемости: поведение
каждого pc фиксировано до запуска. Следствие: рекурсия безопасна «бесплатно» —
свежий фрейм на вызов, конфликтов переменных нет.

## 4. Язык PR

- Синтаксис: `def имя(параметры) = тело`, `entry имя(args)`; succ, вызовы,
  `prec(n, base, step)`.
- Семантика prec: ровно n итераций, счётчик не явлен программисту, граница
  зафиксирована до входа.
- Тотальность: любая программа на языке останавливается на любом входе
  (см. §6 — это LOOP-мир).

## 5. Компилятор pr2sound (v0.4.0)

### 5.1 Конвейер
parse → семантический барьер → лифтинг-карта → кодогенерация → запись sound.json.

### 5.2 Правило молчаливых этапов
Каждый этап обязан валидировать вход; сводка «записано» не выдаётся без проверки.
Фундамент: дефект v0.3 (полулифтинг — имя учтено в таблице слотов, значение не
передано) поймал только исполнитель; компилятор промолчал. Патч v0.3.2 ввёл
семантический барьер до кодогенерации (collect_vars с исключением ссылки на шаг
prec; проверка entry).

### 5.3 Лямбда-лифтинг (v0.4.0)
Замыкания реализуются статически: свободные имена prec-шага поднимаются
дополнительными аргументами вызова, параметры шага расширяются. Магия целиком в
компиляторе: новых опкодов нет, только вырос nargs. Механика:
- prec_steps + build_lift_map: объединение свободных имён по всем местам вызова
  шага (шаг может зваться из разных функций);
- compile_prec: перед CALL — LOAD каждого поднятого имени, nargs = 2+len(extra);
- compile_program: FnCompiler(name, params + lift[name]).

**Барьер v0.4.0:** свободное имя шага обязано найтись среди видимых имён
вызывающего (параметры плюс собственные поднятые имена). Негативный тест:
`weird.pr` — шаг h из mul, вызванный из функции без имени a — обязана падать с
NameError про видимость. Замечание: проверка свободных имён тела тут бессильна —
ловит только проверка видимости.

### 5.4 Открытый вопрос MM-3
Транзитивные свободные имена: цепочки шагов, где свободное имя шага ссылается на
переменную, поднятую на уровень выше. Требует цикла до фикспоинта; для fact не
понадобилось, для глубин самоприменения — понадобится.

## 6. Теоретическая рамка

- **LOOP-программы (Мейер–Ритчи, 1967).** Классика «машины, исполняющей только
  примитивно рекурсивные функции»: LOOP x DO … END с границей, зафиксированной
  до входа. Теорема: вычислимость LOOP-программ ≡ PR. Наш prec — тот же
  конструктив в функциональной форме; соответствие точное, не «по духу».
- **ТМ с часами.** Эквивалентная линза: ТМ с заранее выданным пределом шагов
  вычисляет ровно PR-функции.
- **Сложность.** Время работы PR-программы само примитивно рекурсивно →
  у кост-моделей существуют замкнутые формулы. Прогнозы «записей = f(вход)» —
  привилегия LOOP-мира, а не удача.
- **Граница язык/байткод.** Язык (то, что порождает pr2sound) — LOOP: компилятор
  есть ограничитель выразительности. Байткод с обратными прыжками — тьюринг-полон;
  run_sound на вечном цикле честно зависнет. «Примитивность» обеспечена
  компилятором, не машиной.
- **Непримитивность.** Аккерман растёт быстрее любой PR-функции — не выразим в
  языке ни при каком лифтинге; тест на границе после MM-4.

## 7. Машина Тьюринга: связь

### 7.1 Дорога вниз (mathmachine → ТМ)
Машина — конечный автомат плюс три контейнера; компилируется в ТМ механически:

| Контейнер mathmachine | На ленте ТМ |
|---|---|
| Массив инструкций | отдельная неизменяемая зона (гарвардское разделение) |
| Слоты живых фреймов | зона стека фреймов, растёт вправо |
| Стек операндов | своя зона |
| pc, V, cid | по числу (унарно или двоично) |

Грубая оценка 15–25 состояний при алфавите 7–8 символов. Такт mathmachine
развёртывается в десятки шагов ТМ — вопрос констант, не принципа. Так как код —
данные на ленте, та же ТМ с другой программой на входе — универсальная машина;
run_sound — она, с лентой, заменённой словарями.

### 7.2 Дорога вверх (ТМ → mathmachine)
Ограниченная симуляция выразима уже сейчас: конфигурация ТМ кодируется гёделевым
номером (произведение степеней простых), шаг переходов — PR, тогда
`tmsim(T, cfg0) = prec(T, cfg0, step)` — «прогони T тактов». Неограниченный
вариант — после MM-4. Отсюда точная диагональ: mathmachine всегда сжимается в ТМ
(мы тотальны), ТМ в mathmachine — только с часами.

### 7.3 Репетиция таблиц переходов
Унарные succ и add отрепетированы на ленте: succ — 7 шагов; add — перенос
единиц из блока b в блок a, структура таблицы воспроизводит prec (состояние
«маркер на '_'» = JZ; H = завершение). Первый класс ошибок витка — стартовые
состояния (забытые точки входа таблиц); систематическое смещение +1 у add —
одна структурная ошибка, не случайность.

## 8. Неразрешимость и выразимость (MM-EXP)

### 8.1 Скелет доказательства (перенос Тьюринга/Чёрча)
1. Диагональ: допущение решателя остановки → программа D, зависающая тогда и
   только тогда, когда решатель говорит «остановится». Код-как-данные в проекте
   бесплатен: sound.json — формат данных.
2. Арифметизация: конфигурация = гёделев номер (2^pc · 3^V · 5^(стек) · 7^(фреймы)…);
   такт-функция PR (проверяемо кодом: run_sound по тактам, каждая ветка опкода —
   конечная арифметика).
3. Остановка = Σ₁: HALT(M,w) ⟺ ∃T Reach_M(T,w), Reach — PR.
4. Мосты: β-лемма Гёделя (PR-предикаты определимы формулами ИП, построение
   эффективно) → σ_{M,w} := ∃t Halt_M(t); Σ₁-полнота и Σ₁-корректность Q;
   полнота Гёделя: M останавливается ⟺ ⊨ φ_{M,w}.
5. Замыкание: разрешимость общезначимости → разрешимость остановки → противоречие.

| Ингредиент доказательства | У нас |
|---|---|
| Машина M + вход w | sound-файл + слоты main |
| Код-как-данные | sound.json |
| Конфигурация как число | общий модуль с tmsim.pr |
| PR-ность такт-функции | run_sound по тактам |
| Эффективное (M,w) → φ | будущий pr2form |
| Неограниченный ∃t | mu (MM-4) |
| Сертификат остановки | протокол тактов (fact: T=194, 3221 записей) |

### 8.2 MM-EXP-1
Общезначимость ИП не выразима в PR-языке: PR-программа для valid(φ) дала бы
решатель остановки. Первый строгий результат вида «задача не выразима ни при
каком лифтинге» — фундаментальная граница, в отличие от снятых (мёртвый
параметр, один аккумулятор). Проверяемая часть — одношаговость и PR-ность
такт-функции.

### 8.3 MM-EXP-2 (мост к mu)
После MM-4 язык умеет: полуразрешать остановку (перебор тактов), перечислять
доказуемые формулы ИП (перебор доказательств). Не умеет отрицать: неостанавливающая
программа и невыводимая формула невидимы. Асимметрия сведений: общезначимость
«жёстче» остановки — её отрицание не перечислимо; два неразрешимых множества
разной тьюринговой степени.

### 8.4 Неразрешимость внутри LOOP-мира
Тотальность убивает вопрос остановки, но не неразрешимость как таковую:
эквивалентность PR-программ как функций и предикат «вычисляет тождественный
нуль» неразрешимы (квантор по всем входам). Кост-модели точны, но «что вычисляет
программа без прогона» — без алгоритма: прогнозы выводятся, не вычисляются.

### 8.5 Методологическое следствие MM-4
Программы с mu могут не останавливаться → в логике отщепляется частичная
корректность; протокол для диагональной D бесконечен → дисциплине нужен
ограниченный префикс протокола. Метод факт-ряда в полной общности — привилегия
LOOP-мира; фиксируется до расширения, чтобы получить чистое «до/после».

## 9. Логика Хоара (MM-5, параллельный трек, не блокирует tmsim)

- Динамика (mm_pred) и статика (исчисление) — зеркала: инвариант на 3221 записи
  говорит «в этом прогоне»; тройка {P} c {Q} — «во всех прогонах».
- Правило для prec (структурированный цикл с фиксированным числом итераций):
  база I(0, base), шаг {I(k,acc)} step {I(succ k, acc')}, заключение {true} prec {I(n,res)}.
- Композиция: лестница succ → add → mul → fact оказывается лестницей доказательств;
  value=120 третьей дорогой — выводом, без тактов.
- Логика стоимости: кост-модели перечитываются как {P} c {T ≤ F(вход)}; для prec
  граница линейна по построению.
- Уровень тройки: байткод-аксиомы на опкоды (фреймы попарно различимы — без кучи
  сепарационная логика не потребуется). Язык утверждений: линейный фрагмент
  (равенства acc = C1·k + C0); нелинейность — ограничение трека, не прячем.
  Относительной полноты на линейном фрагменте нет — записываем как ограничение.
- Шаги MM-5: (1) аксиоматика опкодов в спеке; (2) hoare.py: генератор VC +
  символическая проверка линейных равенств; (3) аннотации mul.pr/fact.pr;
  (4) обязательный негативный тест — аннотация acc = k+1 для fact обязана дать
  ложный VC (без него трек повторил бы грех молчаливых этапов); (5) сверка
  деривации inv_balance с 3221 записями.
- Развилка с MM-4: до mu — полная корректность бесплатно (тотальность); после —
  частичная. Запуск трека до mu даёт чистое «до/после» одним исчислением.

## 10. Кост-модели

- **Прямая дорога:** T = n·(prec-итерация + succ + операторы); пользовательские
  вызовы не считаются. Подтверждена на 4 точках (15, 14, 91, 104). Лифтинг
  невидим прямой дороге (91 не сдвинулся) — вызовы бесплатны в тарифе.
- **Машина:** тело add(·,b) = 17b+12 записей; mul(L,b) = b(17L+29)+16.
  Подтверждено на 4 точках (135, 933, 1336, 1064) и выведено до прогона для
  fact(5): 3221 = Σ C_mul(59,106,204,540,2202) + fact-обвязка 77 + 5×6 + 3.
- Урок №4: прогноз обязан пересчитываться от программы (осечка mul8 в репетиции —
  на мне: заменён литерал, забыт счётчик в entry → 56, а не 64).

## 11. Дорожная карта

1. **tmsim.pr** (следующий шаг, общий с MM-EXP): модуль гёделева кодирования
   конфигурации (лента/головка/состояние → показатели простых), такт-функция
   через add/mul; одно применение — ограниченная симуляция, второе — φ_{M,w}.
2. **MM-4: оператор mu.** Язык перескакивает из PR в тьюринг-полное. Первое новое
   поведение — полуразрешимость. Первая неисполняемая программа — диагональная D;
   первый прогноз вида «не останавливается». Новые инструменты: протокол-префикс.
3. **Аккерман** — тест на границе: не выразим в PR, выразим через mu/общую рекурсию.
4. **MM-5: Хоар** — параллельный трек по §9.
5. **MM-EXP: pr2form** — эффективное построение формул по программам.
6. **Отложено: pow(2,8)** — первая квадратичная прямая дорога (рост, которого не
   было ни в одной из шести строк); строится на существующей машине.

## 12. Уроки журнала (актуальные)

1. Совпадение на неразличающих случаях не подтверждение.
2. Исходник этапа — тоже данные: раскладка кода закрыла спор о 54 инструкциях без прогона.
3. Молчаливый этап посреди конвейера опаснее падающего: два внешних рубежа отработали, центр пропустил.
4. Модель стоит на новой точке, когда падает арифметика прогноза — но тогда строка закрывается «подтверждена», не «предсказана».
5. Стартовые состояния — часть контракта вызова (виток ТМ: succ звали из состояния A, add не умел сканировать до +).
6. Систематическое смещение на всех точках — признак одной структурной ошибки (+1 единица у add: сепаратор/маркер).
7. Мой класс ошибок исполнителя в репетиции дважды: адрес возврата читался после снятия фрейма — читать до pop.
8. Ошибки обещанных программ ловятся репетицией до живого прогона: шаг fact из спеки давал 64, а не 120 (направление умножения: mul(a,b) вычисляет b×a; правильно h2(k,acc) = mul(acc, succ(k))).

## 13. Открытые вопросы

- Стек-в-фрейме: альтернативная машина (изоляция стека по фреймам) — зафиксировано как вариант дизайна.
- MM-3: транзитивный лифтинг (цепочки шагов, фикспоинт свободных имён).
- Протокол-префикс для неостанавливающихся программ (нужен после MM-4).
- pow(2,8): прогнозы квадратичной прямой дороги — отложить до после tmsim или совместить.
