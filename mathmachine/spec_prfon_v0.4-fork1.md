# СПЕЦИФИКАЦИЯ «ПР-ФОН» — ФОРК ИЗ ДИАЛОГА

Версия: v0.4-fork1 (реконструкция из диалога от 2026-11-24)
Статус: сводная спецификация прямой дороги (run_pr.py v0.3) и звукового слоя.
Маркировка: [ПОДТВ.] — зафиксировано и проверено прогонами в диалоге;
[РЕКОНСТ.] — восстановлено по памяти диалога, детали требуют пересъёмки.

---

## 0. Назначение

Проект — верифицируемое исполнение примитивно-рекурсивных вычислений:
одна и та же программа исполняется двумя дорогами,
и результат сверяется между ними.

- **Прямая дорога** — интерпретатор исходного ПР-языка (run_pr.py).
- **Звуковая дорога** — компиляция в ленточную машину (pr2sound.py)
  и исполнение машинной программы (run_sound.py).

Сверка идёт по трём уровням (см. §2.6): значение, cross-check прямой↔звук,
детерминизм (два независимых прогона, идентичные протоколы).

## 1. Прямая дорога: язык и интерпретатор

### 1.1. Программа

Программа — набор определений и одна точка входа:

    def имя = выражение
    entry имя(арг1, арг2, ...)

Формат entry: `entry add(5,3)` — без двоеточия. (Восстановление v0.4
по ошибке писало `entry add(5,3):` — лексер это не принимает.) [ПОДТВ.]

### 1.2. Встроенные схемы

- `z` — нулевая функция.
- `s` — следование.
- `pi(n, i)` — проекция: (n мест, номер аргумента).
- `comp[f, g1, ..., gk]` — композиция.
- `prec[f, g]` — примитивная рекурсия.

### 1.3. Конвенция prec: счётчик — первый аргумент

База `f(0, x)`, итерации `g(j, v, x)`, где j — счётчик итераций,
v — накопленное значение. Видна прямо в v0.1-коде: `g(0, x)` в базе,
`h(j, v, x)` на итерациях. [ПОДТВ.]

### 1.4. Решение №3: z — семейство Z_n

`z` — нулевая функция на **любой** арности (пермиссивная, без проверки
арности). Строгая нульместность отвергнута: канонический `mul` требует
двухместного нуля в базе prec — `comp[z, pi(2,2)]` на паре (0, x);
при строгой арности такой вызов невозможен в принципе, и весь тестовый
корпус рушится. Пермиссивность — не умолчание, а задокументированное
решение в каноне теории примитивно-рекурсивных функций. [ПОДТВ.]

### 1.5. Решение №4: итеративный вычислитель

Рекурсивный вычислитель v0.1 заменён на итеративный с явным стеком кадров
— без единого рекурсивного вызова. Риск RecursionError снимается не для
больших n в prec (prec и в v0.1 итерировал циклом), а для **выраженной
вложенности**: цепочка из 5000 вложенных def падает в v0.1 с
RecursionError (exit 1), в v0.2+ проходит за ~0,1 с. Семантика и метрика
не меняются: регрессия байт-в-байт. [ПОДТВ.]

### 1.6. Решение №6: запрет перекрытия имён

Имена атомов словаря и схем (`plus`, `mul`, `z`, `s`, `pi`, `comp`,
`prec`, `def`, `entry`) зарезервированы. Парсер отклоняет
`def такое-имя` с ошибкой разбора:

    error: def: имя 'mul' зарезервировано (атом словаря или схема);
    переопределение запрещено (v0.3)

Цена решения: собственное умножение проекта живёт под именем `mymul`.
Причина: в v0.1 builtin-проверка в call() стоит раньше проверки defs —
узел `name mul` внутри чужого тела резолвится в атом, тело def
недостижимо (мёртвый код). Для системы, чья ценность в верификации,
«одно имя — две программы» хуже неудобства. [ПОДТВ.]

### 1.7. Семантика comp[f] (отзыв раннего утверждения)

В аддендуме v0.3 было записано «comp[f] ≡ f» — **неверно**. Прогон
comp[z](5) показал: comp с пустым списком аргументов вызывает f с
**нулевой арностью**, а не с аргументами внешнего вызова.
Точная семантика: comp[f] — нульместная обёртка, где f вычисляется
без аргументов. [ПОДТВ. — отзыв + замена]

### 1.8. Метрика и канонические тесты прямой дороги

Метрика — число шагов вычислителя (материал для sound-сверки).

| Программа | Entry | Значение | Шаги |
|---|---|---|---|
| add.pr | add(5,3) | 8 | 5 |
| mul.pr | mymul(6,7) | 42 | 112 |
| fact.pr | fact(5) | 120 | 12 |
| fact.pr | fact(7) | 5040 | 16 |
| fact.pr | fact(8) | 40320 | 18 |
| fact.pr | fact(9) | 362880 | 20 |
| fact.pr | fact(20) | 2432902008176640000 | 42 |

Эмпирическая формула fact(n): 2 + 2n шагов. [ПОДТВ.]

### 1.9. Канонические определения корпуса (РЕКОНСТ. по таблице)

- add — база prec есть pi(2,2) (канон add(0,y)=y).
- mymul — повторное сложение, рекурсия по накопителю; канонический
  прогон 112 шагов.
- fact — база s(z), умножение — builtin mul.

## 2. Звуковой слой: компилятор и ленточная машина

### 2.1. Архитектура

pr2sound.py компилирует ПР-программу в машинную программу ленточной
машины; run_sound.py исполняет её. Каждой переменной — своя лента;
значения — в **унарном кодировании** (v0.1-кодировка, сохранена по
решению владельца: сначала сверить дороги на малых входах, позиционное
кодирование — отдельная версия транслятора с тем же протоколом).

Устаревшее различие: в исходном трансляторе ключи `builtin:mul/2` и
`mul/2` различались. После решения №6 (запрет перекрытия) различие
неактуально — при восстановлении транслятор можно упростить. [РЕКОНСТ.]

### 2.2. Операции машины

- `CP src→dst` — перенос; семантика — **добавляющий** перенос
  (см. §2.3).
- `Z x` — обнуление ленты.
- `JZ x, метка` — условный переход (лента пуста).
- `JMP метка`, `CALL подпрограмма`, `RET` — переходы/вызовы.
- `INC x` — инкремент ленты (входит в состав CP).

### 2.3. Решение: CP — добавляющий перенос

Реализация CP (перенос через scratch с восстановлением источника,
5n+2 шагов) не обнуляет приёмник: **dst += src**, источник
восстанавливается. Вскрыто вживую дважды:

1. Накопитель prec-цикла удваивался на каждой итерации
   (7, 15, 31, 63, 127 = 2^k − 1 вместо линейного роста).
2. Копия накопителя в слоте W накапливалась между итерациями
   (3, 7, 15, ...).

Следствие — правило компилятора: **замена значения требует Z приёмника
до CP**. Замена накопителя в prec-цикле компилируется как:

    Z W;  CP V→W;  Z V;  CALL h → V

[ПОДТВ. — две независимые отладки]

### 2.4. Метрика операций

- CP = 5n + 2, где n — длина источника.
- Противоречие с черновиком разрешено в пользу формулы: **JZ считается
  платным шагом** (чтение ленты), JMP/CALL/RET — бесплатны.
  Формула CP сходится только при таком подсчёте. [ПОДТВ.]

### 2.5. CALL/RET и слоты

- Аргументы передаются через слоты лент.
- RET эмитится как отдельная инструкция — в исходном восстановлении
  номер слота записывался в поле ret без эмиссии RET (баг исправлен
  в четырёх местах: материализация и три builtin-подпрограммы).
- Слоты: фиксированные tmp (W) и аккумулятор (V); фиксированные tmp
  требуют Z перед повторным использованием (см. §2.3). [ПОДТВ.]

### 2.6. Три уровня сверки

1. **check** — значение на звуковой дороге совпало с ожидаемым.
2. **cross-check** — значение звуковой дороги совпало со значением
   прямой дороги на том же входе.
3. **determinism** — два независимых прогона; протоколы (полные
   протоколы шагов, JSONL) идентичны байт-в-байт.

Детерминизм в v0.4-fork всегда сравнивает полные протоколы.
[ПОДТВ. на add, mul; факт-дорога — см. §2.8]

### 2.7. Сверка на малых входах (восстановленная реализация)

| Entry | Значение (звук) | Машинных шагов | check | cross-check | determinism |
|---|---|---|---|---|---|
| add(5,3) | 8 | 1 641 | OK | OK | OK |
| mymul(6,7) | 42 | 111 833 | OK | OK | OK |

Протоколы: add.sound.jsonl, mul.sound.jsonl (см. диалог). [ПОДТВ.]

### 2.8. Честная оговорка по машинной метрике

Машинные числа восстановленной дороги **отличаются** от канона
первой сессии (add: 1641 против 372; mul: 111 833 против 23 476):
исходный компилятор не сохранился, восстановленный собран строго по
спецификации, но детали CP-границ и передачи аргументов CALL дают
иную цену. Значения сходятся точно, детерминизм и check работают.

Решение: таблицу машинной метрики (включая точку стены) **переснять
на новой реализации**; прежние числа считать каноном v0.1 звукового
слоя, новые — зафиксировать отдельно. [ОТКРЫТО]

### 2.9. Стена унарного кодирования

Унарное кодирование лент упирается в стену по объёму протокола:
fact(8) проходит (~695 тыс. шагов), fact(9) упирается в лимит
2 млн шагов. Это свойство кодировки, не ошибки — снимается позиционным
кодированием лент. [ПОДТВ.]

## 6. Живучесть

Контейнер забывается между сессиями; переживает только то, что
прикладано вручную, и текст диалога. Настоящий документ — копия
спецификации, живущая у владельца. Прежние файлы (run_pr.py v0.3,
pr2sound.py, run_sound.py, прежние аддендумы) утрачены из контейнера
и восстанавливаются по этому документу.
