# Спецификация Math Machine — аддендум: шкала выразимости MM-P

Версия: v0.1 (теоретический слой)
Дата: 2026-11-24
Статус: теоретический аддендум к MM-P v0.2. Язык не меняет; фиксирует классы
выразимости, цены model checking и запретные территории. Все будущие расширения
(MM-1.6, MM-1.7 и далее) обязаны сверяться с этой картой.

## §0. Назначение

Аддендум отвечает на один вопрос: «что MM-P выражает в принципе и за какую
цену?» Ответ нужен, чтобы расширения языка принимались по карте, а не по
интуиции «пригодится». Карта собрана из четырёх теорем — их статусы и границы
перечислены в §2, ограничения, которые мы из них выводим, — в §3.

## §1. Четыре уровня MM-P

Язык раскладывается на четыре ортогональных уровня. Каждый нижний уровень
живёт без верхних — это осознанный дизайн, проверенный selftest'ами v0.1
и v0.1.1 (см. spec_mm_mm1_v0.1.md, spec_mm_mm11_v0.1.md).

### L0 — точечный слой (FO над записью)

Конструкции: forall/exists/exists1, and/or/not/implies (Kleene), сравнения,
арифметика термов, mem по списку литералов, доступ к полям записи
(s.op, s.state.V, s.args[i], s.sp).

- Выражает: свойства отдельной записи («аккумулятор неотрицателен на каждом
  шаге», «op — из разрешённого набора»).
- Цена проверки: O(N), один полный скан.
- Семантика: Клини, полный скан — вердикт не зависит от порядка записей
  (D-MM1.5-2). Ошибка поля/типа — UNSUPPORTED, не ложь (трёхзначная логика).

### L1 — позиционный слой (FO над словом)

Конструкции: соседняя пара (forall [a b] ...), after/before.

- Выражает: локальные переходные свойства («op не меняется вне CALL/RET»,
  «монотонность аккумулятора по всей ленте»).
- Теорема-опора: Мак-Наутон–Паперт — FO[<] над словами задаёт в точности
  star-free языки; Бюхи–Элгот–Трахтенброт — MSO над словами = регулярные
  языки, перевод эффективен в обе стороны.
- Ключевое отрицание: скобочная структура CALL/RET (язык Дайка) не регулярна,
  следовательно не выразима ни в FO, ни в MSO над позициями слова. Если бы
  протокол был чистой лентой записей без поля depth, инвариант «каждому CALL
  найдётся парный RET» был бы не выразим никакой формулой — не «дорого»,
  а невозможно.
- Цена: O(N) для соседних пар; after/before — O(1) на проверку: позиция —
  свойство носителя, не поле записи.

### L2 — data-слой (bind как freeze-квантификатор)

Конструкция: bind r (where G) B — регистр: запомнить запись, найти дальше
совпадение по равенству данных, например (= r.depth s.depth).

- Выражает: парность CALL/RET, структуру prec-цикла на дистанции («RET
  возвращает собственный V», «между CALL и RET аккумулятор монотонен»).
- Теоретический контекст: слова с данными (data words) — позиция несёт
  значение из бесконечного домена, сравнимое только на равенство. Каноника —
  логика и XPath над XML-деревьями (Боянчик, Швентик, Сегуфен), регистровые
  автоматы; для CALL/RET-трасс — visibly pushdown automata (Алюр, Мадхусудан).
  Наш bind — это freeze-квантификатор с одним регистром, поиском только
  вперёд и без переключений прошлое/будущее.
- Главные факты теории data words: сатисфицируемость формул в общем случае
  неразрешима (в том числе для FO с равенством данных и двумя переменными);
  отдельные фрагменты с регистрами дают не примитивно-рекурсивную сложность.
- Спасение MM-P: мы выполняем только model checking — формула фиксирована,
  протокол дан. Для нашего фрагмента проверка линейна с множителем:
  O(N·L), где L — средняя длина сканируемого хвоста до совпадения;
  худший случай O(N²).
- Ключевое отрицание: вопрос «существует ли протокол, на котором формула
  истинна» — вне языка навсегда (см. §3.1).

### L3 — арифметический слой (агрегаты)

Конструкции: (count v (where P)), (sum v t (where P)); кандидат MM-1.6 —
(prod ...).

- Выражает: счёт и свёртки («число RET равно числу CALL», «сумма
  возвращённых значений равна результату на HALT»).
- Теорема-опора: FO не выражает счёт (пример Эренфойхта–Фраиссе: «чётное
  число записей» не выразимо в FO над словами). Территория с подсчётом —
  арифметика Пресбургера и FO со счётными расширениями.
- Следствие: L3 — настоящее расширение выразимости, не сахар. Тотальность
  агрегата (ошибка внутри тянет UNSUPPORTED, D-MM1.5-3) держит семантику
  честной: агрегат по частичному протоколу не имеет смысла.

## §2. Теоремы, на которые опирается карта

1. Бюхи–Элгот–Трахтенброт: MSO над словами = регулярные языки; перевод
   формула → автомат эффективен. Следствие для нас: любой инвариант,
   выразимый в MSO над позициями, проверяется автоматом за O(N) — верхняя
   граница цены L0/L1, и она уже достигнута нашим сканом.
2. Мак-Наутон–Паперт: FO[<] над словами = star-free языки. Следствие:
   наш L1 не выражает «чётное число записей» и любую проверку подсчёта —
   за ними нужно идти в L3.
3. Нерегулярность языка Дайка: парность скобок не выразима в FO/MSO над
   позициями. Следствие: без поля depth наш класс стековых инвариантов
   пуст; поле depth — единственный носитель стековой структуры протокола,
   и bind — единственный механизм, который его читает.
4. Теория data words (Боянчик и др.): сатисфицируемость неразрешима;
   model checking ограниченных фрагментов — разрешим и линеен. Следствие:
   различие «проверить данный протокол» / «существует ли протокол» —
   не упрощение, а граница между разрешимым и неразрешимым (§3.1).
5. Эренфойхт–Фраиссе: FO не отличает чётность. Следствие: агрегаты —
   расширение выразимости, а не синтаксический сахар.

## §3. Границы, которые мы обещаем не переступать

1. Запрет на сатисфицируемость. MM-P проверяет формулу на данном протоколе.
   Вопрос «существует ли протокол, на котором инвариант истинен или ложен» —
   вне языка и вне спецификации навсегда: для data-слоя он неразрешим. Если
   когда-нибудь понадобится поиск контрпримера по классу протоколов — это
   отдельный слой с отдельной спецификацией, не MM-P.
2. Индексная чистота. Свойство не зависит от порядка записей в файле:
   позиция используется только через явные after/before. Вердикт формулы
   воспроизводим при перестановке строк jsonl (свидетели несут свои позиции).
3. Тотальность агрегатов. Ошибка внутри count/sum — всегда UNSUPPORTED,
   не ложь. Агрегат отвечает «насчиталось ли честно», а не «насколько
   насчиталось».
4. Bind — поиск, не тотальность. «Нет совпадения» = FAILED со свидетелем
   (сам CALL); ошибки до совпадения подавляются со счётчиком
   (D-MM1.5-3/4). Теоретическое обоснование различения: поиск — дешёвая
   операция с частичной семантикой, агрегат — тотальная.
5. Никакой памяти между утверждениями. Правило независимости (спека MM
   v0.1, §правило) — каждое утверждение проверяется с нуля, результаты
   и статусы других утверждений не используются. Семантика детерминирована
   и не зависит от истории проверяющего.

## §4. Карта цен (model checking)

Цена на протоколе из N записей; столбец «измерено» — вживую на selftest.

| Конструкция                      | Цена                    | Измерено |
|----------------------------------|-------------------------|----------|
| L0 forall/exists (полный скан)   | O(N)                    | да (v0.1) |
| L1 соседняя пара                 | O(N)                    | да (v0.1.1) |
| L1 after/before                  | O(1) на проверку        | да (v0.1.1) |
| L2 bind на верхнем уровне        | O(N·L), худший O(N²)    | частично: 11 зап. → 44 проверки (множитель ~4, v0.2) |
| L2 вложенный bind внутри forall  | O(N^k), k = глубина     | нет — только экстраполяция |
| L3 агрегат на верхнем уровне     | O(N)                    | да (v0.2) |
| L3 агрегат внутри forall         | O(N²)                   | нет — ожидаемая стена |

Эталонный масштаб противника: полный протокол mul(6,7) — 111 833 записи.
Вложенные квантификаторы на нём дают порядка 10^10 проверок — стена,
известная как MM-3. Измерение на живом протоколе (fact-row, дорога Б) —
обязательное условие любых решений по MM-3 и по предохранителю §5.

## §5. Кандидат-предохранитель MM-1.8: ограничение вложенности bind

Теория разрешает вложенные bind, но цена растёт как N^k. Кандидат на
фиксацию: bind не внутри bind — один уровень регистров, остальное через
L0/L1 внутри тела. Сохраняет весь класс стековых инвариантов prec-цикла,
держит цену ≤ O(N²). Решение откладывается до измерений на реальном
протоколе — не проектировать предохранитель без измеренного противника.

## §6. Что карта даёт ближайшим шагам

- MM-1.6 (prod): теоретически безобиден — тотальный агрегат того же класса,
  что count/sum. Добавлять по живой потребности, без страха.
- MM-1.7 (поддиапазоны): выразимости не расширяет (L1+L2 покрывают), чистая
  эргономика — статус «сахар» теперь теоремно обоснован.
- MM-1.4 (имена полей протокола): теория не спасает от неверной привязки
  имён — только живой прогон fact-row на реальном run_sound.py.
- MM-3 (компактные сертификаты): противник измерен заранее — 111 833 записи,
  ~10^10 для вложенных квантификаторов. Требование к компактному формату:
  сохранять проверяемость всех четырёх уровней L0–L3; если сжатие выбивает
  какой-то уровень — формат не принимается.

## §7. Резюме одной строкой

MM-P v0.2 = FO-ядро (L0/L1, star-free, линейный скан) + data-равенство
вместо стека (L2, bind, линейно с множителем) + тотальные агрегаты (L3,
за границей FO, привкус Пресбургера). Точка выбрана сознательно: вся
дешевизна model checking куплена отказом от двух запретных территорий —
сатисфицируемости и позиционной парности скобок без поля depth.

## §8. Литература (для чтения, не для цитирования в спеке)

- Büchi–Elgott–Trakhtenbrot: MSO над словами = регулярные языки.
- McNaughton–Papert: FO[<] = star-free.
- Dyck language: классика нерегулярности.
- Alur, Madhusudan: visibly pushdown automata — каноника CALL/RET-трасс.
- Bojańczyk, Schwentick, Segoufin: логика над data words; регистровые
  автоматы; два переменных с равенством данных.
- Immerman: descriptive complexity (FO = AC0) — перспектива для будущих
  вопросов о классах проверяемости.
- Runtime verification / monitoring: трёхзначная семантика на трассах —
  независимая традиция, совпавшая с нашей verified/failed/unsupported.
