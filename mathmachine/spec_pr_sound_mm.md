## 1. Язык PR

### 1.1 Программа
- Строки: `def имя(парам) = выражение` и `entry имя(арг1, ...)`.
- Комментарий — строка, начинающаяся с `;`; пустые строки игнорируются.
- entry обязателен, ровно один.
- Нормализация: построчный rstrip, пустые строки отбрасываются.
  sha256 считается по нормализованному тексту — отпечаток программы,
  одинаковый у обеих дорог на одном источнике.

### 1.2 Выражения
- Литералы — неотрицательные целые.
- Имена: параметры функции; свободные имена в прямой дороге берутся из
  окружения места вызова.
- Арифметика: +, -, *; приоритет * выше, левая ассоциативность; скобки.
- succ(x) = x + 1.
- prec(c, g, h) — примитивная рекурсия. Счётчик — ПЕРВЫЙ аргумент.
  f(0) = g; f(n+1) = h(n, f(n)); итерации h(i, acc) для i = 0..c-1.
  h — имя функции ровно с 2 параметрами.
- ifz(c, t, e) — при c = 0 значение t, иначе e. Вычисляется ровно одна ветка.
- spawn(f(a1, ..., an)) — ровно один вызов ОПРЕДЕЛЁННОЙ пользователем функции.
  ifz, spawn, await и встроенные внутри spawn — ошибка.
- await(spawn(...)) — аргумент только spawn-выражение.
  Голый spawn вне await — SyntaxError.

### 1.3 prec — семантика и ловушки
- Шаг h исполняется в окружении, НАСЛЕДОВАННОМ от места вызова, плюс
  {первый параметр: i, второй: acc}. Потеря окружения — тихий дефект
  (значения считаются, но не те).
- Счётчик шагов: каждая итерация prec даёт +1 в steps прямой дороги.

### 1.4 spawn/await — решения (MM-6.1)
| Решение | Значение | Следствие |
|---|---|---|
| Момент spawn (прямая дорога) | eager: потомок вычисляется сразу, await распаковывает | value совпадает с машиной на чистых функциях |
| Дисциплина | только spawn-под-await, только обычная функция | await чужого cid невозможен по построению |
| Понижение (компилятор) | args вычисляются в вызывающем → SPAWN [fn, n]; AWAIT берёт cid со стека | машина знает только инструкции |

- Счётчики tasks и awaits (число spawn и await) — в steps НЕ входят.
- Лифтинг (компилятор): свободные имена тела шага prec поднимаются в
  дополнительные параметры вызова. Свободные имена в spawn-аргументах —
  ошибка барьера ДО кодогена: потомок получает только свои параметры.
- Прямая дорога не ведёт очередь: свободное имя в spawn-аргументе ловится
  динамически (NameError) — свойство дороги, не дефект.

### 1.5 Сравнимость дорог
| Величина | Прямая | Машина | Сравнимо |
|---|---|---|---|
| value | 8 | 8 | ДА — главный канал сверки |
| tasks / spawns | 15 / 14 | 15 / 14 | ДА |
| awaits | 14 | 28 | НЕТ — разные единицы |
| steps | 46 | 489 | НЕТ — семантика против инструкций |

- Разложение steps проверяется подстановкой, не подбором до суммы
  (fib(5): 26+5 bin + 10 prec-итераций + 10 succ = 46).
- sha256 сравним всегда.

## 2. Звуковая машина (MM-6)

### 2.1 Формат sound-v0.3
- JSON: fmt, src_sha256, main.code, fns{name: {code}}.
- Инструкция — пара [op, arg] (без аргумента — null).
- Код: main.code, затем функции конкатенацией; метки разрешаются при
  компиляции в абсолютные pc; starts[name] — адрес входа; в конце
  страховочный HALT.
- run_sound проверяет fmt; чужой формат — отказ с внятным сообщением.

### 2.2 Инструкции
| Инструкция | Аргумент | Действие |
|---|---|---|
| PUSH n | число | push n |
| LOAD i | индекс | push locals[i]; вне слотов — MachineError |
| STORE i | индекс | pop → locals[i] |
| ADD / SUB / MUL | — | b=pop, a=pop, V=a op b, push V |
| JZ L | pc | pop v; запись с args=[v]; переход при v=0 |
| JMP L | pc | запись args=[]; безусловный переход |
| CALL [f,n] | [имя, n] | снять n аргументов; cid+=1; фрейм {ret, locals=args, depth+1, cid} |
| RET | — | pop → V; фрейм снимается; переход по frame.ret; запись несёт cid фрейма |
| SPAWN [f,n] | [имя, n] | снять n аргументов; новая задача с базовым фреймом ret=None; push cid родителю |
| AWAIT | — | peek: cid НЕ снимается; готов → resume, cid заменяется значением; не готов → suspend, парковка |
| HALT | — | завершение задачи 0 — конец машины |

- cid: монотонный счётчик последнего вызова задачи; в записях инструкций —
  текущий, в записи RET — cid снимаемого фрейма.
- Запись протокола — на каждую исполненную инструкцию:
  {pc, op, args, state:{V}, depth, cid, task}. steps = число записей.
- Протокол v0.4 добавляет поле task во ВСЕ записи.

### 2.3 Многозадачность
- Задача: tid, pc, V, стек, фреймы, cid, родитель, статус, почтовый ящик.
- Завершение задачи — исчерпание базового фрейма (ret=None). Пустота
  фреймов — НЕ признак завершения: у main первый фрейм — обычный
  CALL-фрейм (баг ложного завершения main, пойман в репетиции).
- Почтовый ящик: значение потомка пишется в parent.mail сразу; родитель
  просыпается только по своему awaited-cid — чужие результаты не будят
  и не теряются.
- Планировщик: run-to-block; из готовых — минимальный tid. Чистые функции
  → детерминизм: двойной прогон даёт идентичные протоколы.
- Детектор тупика: нет готовых при паркованных → MachineError с перечнем
  «кто кого ждёт». Молчаливых зависаний нет.
- RESULT: запись при завершении задачи (значение, task).

### 2.4 Двухосевая модель (инварианты)
- Ось вызовов: CALL-RET парами по cid внутри каждой задачи.
- Ось порождений: SPAWN-RESULT 1:1.
- Следствие: RET = CALL + RESULT (RET обслуживает и возвраты, и завершения).
- AWAIT: ровно 2 исполнения на потомка — suspend + resume.
- Теорема-кандидат: при await(spawn(...)) в теле второй AWAIT пары
  подвешивает всегда; SUSPEND >= 1 на пару; для fib(5) SUSPEND = RESUME = 14.
- VALUES: мультимножество значений потомков — слепок дерева вычислений.

### 2.5 Эталон fib(5) — фиксированная точка
- 53 инструкции (fib 13, sp2 12, add 21, g 4, main 3).
- Исполнение: 489 инструкций / 503 записи; CALL=25 (1 fib + 7 sp2 + 7 add
  + 10 g), RET=39=25+14, SPAWN=RESULT=14, AWAIT=28.
- Первая SUSPEND — запись N14; префикс 0..13 без единой развилки.
- VALUES: {1:8, 2:3, 3:2, 5:1}.
- Протокол сверен двумя независимыми реализациями — дословно.

## 3. mathmachine

### 3.1 Роль и интерфейс
- mm_pred.py — предикатный верификатор. Вход: протокол .sound.jsonl и
  файл(ы) инвариантов .mmx. Выход: JSON {verdict, unknown_count}.
- VERIFIED — все предикаты выполнены; FAIL — нарушение с указанием записи;
  unknown_count — число проверок с неопределённым исходом.
- Целевое состояние: VERIFIED, unknown_count = 0.
- Протокол — единственный источник истины: предикаты не читают исходник.

### 3.2 Пакет инвариантов (v0.4)
- inv_nonneg.mmx — все значения протокола (V, аргументы, результаты)
  неотрицательные целые.
- inv_pair.mmx — каждая CALL имеет парный RET в той же задаче
  (сопоставление по cid); фреймы корректны.
- inv_balance.mmx — баланс стека и фреймов на границах задач.
- inv_spawa.mmx — ось порождений: SPAWN = RESULT; AWAIT завершается ровно
  один раз на потомка; потомок ждёт только родителя; RET = CALL + RESULT.

Уточнение v2 inv_spawa (история ошибки): считались ИСПОЛНЕНИЯ AWAIT —
по два на пару, инвариант врал на всех парах. Честная единица —
ЗАВЕРШЕНИЯ ожидания: одно на потомка.

### 3.3 Синтаксис .mmx
- Точный синтаксис живёт в файлах на диске; выше зафиксирована семантика.
  Для записи грамматики в спеку — прислать файлы.

## 5. Дисциплины (уроки, ставшие правилами)
1. Файл в контейнере раньше вставки — патчи строятся от снапшота, не от памяти.
2. Ожидание теста проверяется подстановкой значений ДО прогона.
3. Компоненты счётчиков объясняются подстановкой, не подбором до суммы.
4. Запись в протокол — структурно неизбежна: один append на общий путь цикла.
5. Счётчики дорог не сравниваются напрямую — сравниваются value, tasks, sha256.
6. Признаки завершения и готовности проверяются на граничных задачах
   (main — обычная задача с обычными CALL-фреймами).
