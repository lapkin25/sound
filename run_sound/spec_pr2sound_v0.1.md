# Спецификация pr2sound — v0.1 (draft)

Статус: **черновик**. Всё, что не выведено из `run_pr.py` (v0.1) и зафиксированных
договорённостей по sound v0.6, помечено как `РЕШЕНИЕ` и требует утверждения.

Источники:
* `run_pr.py` — синтаксис `.pr`, конвенция `prec`, прямая метрика шагов.
* Разговор (раздел 8 spec_sound_v0.6): звуковой слой = MathMachine
  (ленты-счётчики), реестр шагов, полная история вычислений.

---

## 1. Назначение

`pr2sound.py` — транслятор: берёт программу `.pr` (тот же формат, что парсит
`run_pr.py`) и порождает:

1. **sound-программу** — программу для звукового слоя (MathMachine).
2. **протокол трансляции** — карту соответствия: какое место `.pr` в какой
   фрагмент sound-программы превратился.

Цель: вторая, независимая дорога вычисления. `run_pr.py` исполняет программу
напрямую, `run_sound.py` исполняет sound-программу по шагам с ведением реестра;
результаты сравниваются. Расхождение дорог = баг компилятора или раннера.

## 2. Модель звукового слоя (MathMachine)

Зафиксировано из разговора: ленты-счётчики, примитивные операции, пошаговый
реестр. Конкретный командный набор — `РЕШЕНИЕ`.

Предлагаемый минимальный набор (все операции — над лентами):

| Команда | Смысл | Шагов |
|---|---|---|
| `Z t` | обнулить ленту `t` | 1 |
| `S t` | инкремент ленты `t` | 1 |
| `D t t'` | декремент ленты `t`; если пуста — перейти-заглушка на `t'` (записать 0) | 1 |
| `JZ t lbl` | переход, если лента `t` пуста | 0 (тест) |
| `LBL lbl` | метка | 0 |
| `JMP lbl` | безусловный переход | 0 |
| `CALL f / RET` | вызов/возврат подпрограммы функции | 1 |
| `CP a b` | копировать ленту `a` в `b` (циклом S/D) | len(a) |

Переходы и метки бесплатны в машинной метрике шагов; только действия с лентами
стоят шаг. `РЕШЕНИЕ: подтвердить бесплатность JZ/JMP/LBL`.

## 3. Кодирование чисел

`РЕШЕНИЕ`: **унарное** представление — число `n` есть лента с `n` единицами.
Причины: ленты-счётчики в основе модели; инкремент/декремент атомарны; арифметика
плюс/умножение естественно выражается через S/D-циклы. Плата — размер лент
(см. раздел «Открытые вопросы»).

## 4. Кодирование схем

Конвенция prec наследуется из `run_pr.py` и **не меняется**: счётчик — первый
аргумент, `g(n, x)` при нулевом шаге, `h(j, v, x)` на итерациях
(канон: `add(0,y) = y`).

| Схема | Кодирование |
|---|---|
| `z` | `Z out; RET` — 1 машинный шаг |
| `s` | `S out; RET` — 1 шаг |
| `pi(k,i)` | нулевая стоимость: аргумент `i` назначается выходной лентой текущего фрейма (аналог прямого переименования из прямой метрики). `РЕШЕНИЕ: pi не порождает команд, а разрешается на этапе аллокации лент` |
| `comp[f, g1..gm]` | последовательность `CALL gi` (вход — текущий фрейм, выход — временные ленты) затем `CALL f` с лентой-вектором результатов. `РЕШЕНИЕ: точная аллокация временных лент — линейный проход, новые ленты на каждый промежуточный результат` |
| `prec[g, h]` | цикл: сохранить `n` на счётчик; вычислить `g(0, x)`; затем `j` раз от 0 до n−1 вычислить `h(j, v, x)`; результат — лента `v`. Внутренний счётчик `j` — своя лента (не путать с лентой аргумента `n`) |

Каждое имя функции = одна подпрограмма с фиксированной арностью (сверяется с
определением, как в `run_pr.py`).

## 5. Атомы словаря (plus, mul)

Словарь v0.6 объявляет `plus` и `mul` чисто-значимыми. Для звуковой дороги это
развилка:

* **Вариант A (по умолчанию, `РЕШЕНИЕ`): полное раскрытие.** `plus(a,b)` →
  цикл переноса единиц; `mul(a,b)` → вложенный цикл сложения. Плюс: звуковая
  дорога опирается только на базовые операции, верификация полная.
  Минус: цена. Ожидаемая машинная цена `mul(6,7)` — порядка сотен шагов
  (примерно 6×(7+1)+константа ~ 60–80 шагов сложения плюс служебные; точное
  число фиксируем эталонным прогоном после реализации).
* **Вариант B: флаг `--keep-atoms`.** Атомы считаются доверенными, шаг атома
  отмечается в реестре меткой `trusted`. Быстро, но верификация неполна.

## 6. Сопоставление дорог

* **По значению — всегда.** Результат звуковой дороги обязан совпасть с
  результатом прямой.
* **Шаги — только с пометкой.** Прямая метрика (применения схем и атомов,
  `pi` бесплатно) ≠ машинные шаги звукового слоя. `run_sound.py` печатает обе
  величины рядом, но сверяет только значения. `РЕШЕНИЕ: не строить формулу
  пересчёта одной метрики в другую; сопоставление шагов — отдельная задача`.

## 7. Протокол верификации (реестр шагов)

`РЕШЕНИЕ: формат — JSONL, одна строка — один шаг`:

```json
{"n": 1234, "op": "S", "tapes": {"3": 7}, "fn": "add/prec-h", "pc": 41}
```

Поля: `n` — номер шага; `op` — команда; `tapes` — срез изменённых лент после
шага; `fn` — имя подпрограммы (или `top`); `pc` — счётчик команд. Полная история
сохраняется, ничего не режется (соглашение из раздела 8 spec_sound_v0.6).

`run_sound.py` сверяет: (а) финальное значение с прямой дорогой;
(б) собственный реестр с самим собой при повторном прогоне (детерминизм);
(в) при `--check N` — с ожидаемым значением, exit 1 при несовпадении.

## 8. Ошибки трансляции

Наследуются от парсера `run_pr.py` (арность, неизвестные имена, повторные def,
`1 <= i <= k`). Новые:

* `comp` без элементов — отсекается в трансляторе, а не позже (в `run_pr.py`
  это дыра всплывает в проверке арности — там её тоже закроем).
* переполнение лимита шагов реестра — `РЕШЕНИЕ: лимит шагов `--max-steps`,
  по умолчанию 1_000_000; превышение = ошибка, а не тихое зависание`.

## 9. CLI

```
python pr2sound.py program.pr --out sound.json [--proto proto.jsonl] [--keep-atoms]
python run_sound.py sound.json [--proto proto.jsonl] [--entry f(3)] [--check N] [--trace]
```

`--proto` без значения файла пишет в stdout (как `--trace` в `run_pr.py`).
Выходные коды повторяют `run_pr.py`: 0 — ок, 1 — ошибка/несовпадение, 2 — usage.

## 10. Открытые вопросы

1. Канонический текст семантики MathMachine v1.6 — не в руках; командный набор
   раздела 2 и стоимость шагов — предложения, не факт.
2. Формула (или отказ от формулы) пересчёта прямой метрики в машинные шаги.
3. Эталонные машинные числа шагов для `add(5,3)`, `mul(6,7)`, `fact(5)` —
   появятся только после реализации; до тех пор таблица из spec_sound_v0.6
   относится только к прямой дороге.
4. Аллокация лент: переиспользовать временные ленты (экономия) или выделять
   новые на каждый промежуточный результат (простота аудита)? Предлагаю второе
   для v0.1.
5. Унарное кодирование упирается в размер лент: `fact(7)` — лента на 5040;
   `fact(10)` — на 3 628 800. Порог, где нужен переход к позиционному коду,
   не выбран.
