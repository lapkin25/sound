## Закрытые пункты канона (эталон старше текста)

1. Итерация foldlist — **3 шага скелета** (ref операнда, const индекса, part) + шаги тела. Обход бегущим индексом 0..N-1 по фиксированному операнду; tail-цепочки нет.
2. `part` всегда получает список через шаг `ref`; `len`, `tail`, `snoc` — напрямую по хендлу.
3. Индекс — собственный шаг `const`, `part` принимает его хендл (литерал внутри part не эмиттируется).
4. `len` ставится по корню списка-операнда (если операнд — `tail L`, то по L, до снятия головы).
5. Порядок эмиссии: список-база -> len -> якорь аккумулятора -> операнд -> итерации.
6. Порядок аргументов foldlist: **f acc list** (эталон DemoMax). Форма легаси DemoSum (list f acc) — до-канонная эпоха, для новых программ не норма.
7. If: `if c then else`, c!=0 -> then. Обе ветви развёрнуты, невзятая сохранена (в DemoMax мёртвых ветвей нет — if без вложенных вызовов).
8. Сборка списка — поэлементно: const nil, затем (const элемент, snoc) на каждый элемент. Поправка к §4 spec_foldlist v0.1 («один const [...]») опровергнута эталоном.
9. Неиспользуемый факт (n = 8) шагов не порождает.
10. Скалярные факты инлайнятся как const при каждом употреблении (дедупликация запрещена); списочные факты материализуются один раз, дальнейшие употребления — через ref при deref-контексте.
