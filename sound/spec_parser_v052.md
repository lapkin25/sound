# Спецификация парсера Piano — piano_parser.py

Версия: spec v0.6 (заменяет v0.5.1-редакцию). Дата: 2026-11-23.
Статус: заморожена до приёмки; изменения — только записью новой версии.

## 1. Место в стеке

- Вход: программа Sound v0.1 в грамматике Piano frozen v0.5.1; допускается v0.5.2 (cons).
- Выход: журнал шагов формата sound-0.5.1 (заголовок sound-0.5.2 при наличии cons).
- Парсер — эмиттер, не интерпретатор: не вычисляет значений, в колонке значений стоит
  плейсхолдер `?`. Значения заполняет реплей.
- Десугаринг Sound-цепочки — отдельная программа; связка — только формат файла.
- Обоснование разделения ролей: парсер строит журнал, реплей его воспроизводит.
  Ошибка вывода значения внутри парсера была бы скрытым каналом самосогласованного
  дефекта (класс, вскрытый на DemoMaze2) — запрещена по построению.

## 2. Вход и выход

- Входной файл: текст Piano v0.5.1/0.5.2, UTF-8, LF.
- Комментарии `# ...` — в любом месте исходника; в журнал не попадают.
- Выход: файл журнала — заголовок (формат, версия frozen-грамматики), пустая строка,
  строки шагов.
- Строка шага: `tNNNN op arg1 arg2? -> ?`.
- Идентификаторов выхода в строках НЕТ — это канон sound-0.5.1 (эталон DemoMax).
  Соглашение о выходных идентификаторах (правка DemoSum) переносится в примечания
  к реплееру, не в формат. Старые журналы DemoSum/DemoSumPos с идентификаторами —
  легаси, для ворот не используются.

## 3. Лексика

- Идентификаторы: `[a-z][a-z0-9]*`. Зарезервированы имена операций и форм:
  nil, const, snoc, cons, len, ref, part, tail, lt, plus, if, rule, data, foldlist.
- Целочисленные литералы: `-?[0-9]+` (минус — знак литерала, не операция).
- Литералы списков: `[a,b,...]`, литералы кортежей: `(a,b,...)`.
- Инфиксные операции отсутствуют (v0.5.1; прецедент T5). `+` и `-` внутри
  идентификаторов и выражений запрещены.

## 4. Грамматика frozen v0.5.1

- Секции: объявления data, объявления rule.
- Выражения: применение операции (голое и в скобках), литералы (число, nil, список,
  кортеж), ссылка на имя.
- rule: `rule name arg1 arg2 = expr`; аргументы позиционные.
- Bind: ленивый, раскрытие по месту употребления; повторное употребление имени
  порождает новые узлы — дедупликации нет (§6).
- foldlist: `foldlist acc f list` — раскрывается по §7.
- If: `If cond a b` — строгая форма по §7.

## 5. Категории ошибок — три, не две

- GrammarErr — лексическая или синтаксическая ошибка текста.
- DictErr — операция вне реестра; нарушение канона формы (арность, вид операндов).
  Проверка реестра и арности обязательна в ОБЕИХ формах приложения — скобочной
  (правка T2) и голой (правка T3). До правок реестр проверялся только в скобках.
- TranscrErr — текст корректен и словарен, но раскрывающийся журнал нарушает
  ИНВ-Р.1 (ссылки строго назад) или структурные инварианты.
- Смешение категорий — дефект парсера. Правильное распознавание категории —
  часть приёмки (сломы §10).

## 6. Нумерация и bind

- Единый счётчик t0001, t0002, ... на весь журнал. Никаких раздельных s/h-счётчиков
  (фиксация по эталону DemoMax).
- Константы и скаляры нумеруются в общем потоке по мере возникновения.
- ИНВ-Р.1: каждый шаг ссылается только на более ранние. Уточнение (из DemoReverse):
  литеральные аргументы const (`nil`, числа) не являются tid-ссылками и из проверки
  исключаются.
- Дедупликация констант и подвыражений запрещена: одинаковые значения — разные узлы
  (следствие отсутствия равенства кортежей в frozen-множестве).
- Bind — ленивый, обязательный, немонотонная дедупликация: повтор имени — новый узел.

## 7. Разворачивание foldlist и If

- foldlist acc f [x1..xn] разворачивается в явную цепочку:
  len (если нужен размер), затем на каждую итерацию — ref текущего списка, const
  индекса, part, tail, ref хвоста (по канону DemoMax), шаг тела с подстановкой
  аккумулятора и элемента. Аккумулятор — ссылка из предыдущей итерации; на первой —
  якорная константа acc.
- Тело итерации встраивается (inlined) с перенумерацией; ссылок на имена тела
  в журнале после разворачивания нет.
- If c a b: ОБЕ ветви вычисляются (строгость), выбор — один шаг `if`.
  Шаг невзятой ветви присутствует в журнале («мёртвый» плюс — прецедент DemoSum).
- cons L x: список — первым аргументом (конвенция реестра: snoc L x, part L i,
  tail L); правило Sound читается как `cons cur x`. Типизация второго операнда —
  забота реплея (класс «ошибка реплея»), транскриптор типов не знает.

## 8. Формат строк журнала

- Реестр операций: const, snoc, cons, len, ref, part, tail, lt, plus, if.
- const nil — nil как литеральный аргумент: `t0001 const nil -> ?`.
- Значения списков выписываются целиком, без дедупликации и мутаций.
- Заголовок журнала: `# ... sound-0.5.1` либо `# ... sound-0.5.2` (при cons).

## 9. Запреты

- Не вычислять значений в парсере.
- Не вставлять идентификаторы выхода в строки (реплеерская правка).
- Не менять формат вне замороженных версий.
- Не смешивать категории ошибок.
- Не применять инфиксы.
- Не устранять «мёртвые» ветви If — строгость по построению.
- Не дедуплицировать константы.

## 10. Приёмочные ворота

1. Байт-в-байт: DemoMax против внешнего эталона — единственный строгий критерий.
   Путь: парсер строит шаблон с `?`, реплей заполняет значения, результат сверяется
   с эталоном символ в символ (финал 9 — проверка слабая, должны совпасть все строки).
2. Семантические перепрогоны: DemoSum (34 шага, финал 29), DemoSumPos (51, финал 30),
   DemoReverse2 (42, финал [6,2,9,5,1,4,-1,3]) — финалы, ИНВ-Р.1, чекпоинт и рестарт,
   контрольный слом с локализацией на первой расходящейся строке.
3. Шесть контрольных сломов: по одному на каждую категорию с обеих форм приложения,
   с обязательной корректной классификацией (T2/T3 после правок обязаны падать
   как DictErr, не как TranscrErr).
- Принцип: парсер, который не умеет отказываться, так же плох, как парсер,
  который не умеет читать.

## 11. Открытые пункты (вне данной спецификации)

- R4-эталоны — разблокируются после приёмки парсера.
- Ворота Octave/Java, бинарные ворота.
- Вопрос в реестр стиля: лишние ref в каноне DemoMax — обязательный канон или
  допустимая оптимизация.
