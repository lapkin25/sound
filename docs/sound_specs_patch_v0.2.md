# Сводный патч-документ спек Sound — v0.2

Основание: сверка чек-листа раздела 8 TTB и реализации с четырьмя спеками
(SCore v0.3, Addendum v0.2, Language Spec v0.1, TTB v0.1, triomat v1).
Формулировки — готовые фрагменты для дословного переноса в рабочие файлы.

---

## SCore v0.3 → v0.4

### P-01. Семантика widen (замена строки в §«Семантика операций»)

Было: «`widen` (int→float): всегда точен».

Стало:

> `widen` (int→float): округление детерминировано по IEEE-754
> (round-to-nearest-even); для значений, непредставимых точно в double
> (|v| > 2^53), результат помечается событием `coerce` с `lossy: true`.
> «Всегда точен» отменяется: неограниченные целые делают безусловную точность
> невыполнимым обещанием.

Мотивация: прямое противоречие с R-INT3 («Lossy(repr) для значений, не
представимых точно в double»). Семантика T13 (ties-to-even, флаг в журнале)
остаётся эталоном.

### P-02. Разведение слоёв R-INT1 / R-INT2

Добавить в §«Отклонения» или §3:

> R-INT1 — конверсия внутри Sound: точность по факту представимости значения;
> событие `coerce` с `lossy: true` при непредставимости. R-INT2 — граница моста:
> консервативная граница 2^53 (см. патч TTB P-06). Слои различны; расхождение
> границ — не дефект, а разность контрактов «внутри» и «наружу».

## Sound Language Spec v0.1 → v0.2

### P-03. DimVar: правило и примеры (правка §3 и §11)

Правило «IDENT с малой буквы = DimVar» сохраняется; примеры приводятся к нему:
`Matrix[F64, R, 512]` → `Matrix[F64, r, 512]` и аналогично по всему тексту.
Заглавные однобуквенные `C`/`F` резервируются как layout-маркеры слоя моста
(см. патч TRIOMAT §3.1) и не являются DimVar.

### P-04. Таблица конверсий §7 (правка формулировки)

Было: «точные (`F32→F64`, `Int64→Float64` с `Lossy(repr)`)» — оксюморон:
«точные» рядом с Lossy. Стало:

> конверсии dtype — по таблице: точные расширения (`F32→F64`), расширяющие с
> возможной потерей представления (`Int64→Float64` — Lossy(repr) при
> непредставимости), объявленно-потерьные (`F64→F32` — ребро помечается
> `lossy:precision`), запрещённые (`Bool→число` — UndefinedBridge, R-BOOL).

### P-05. Закрытый набор §8 (устранение дублирования)

Перечень `TrioError` в §8 Language Spec заменить ссылкой:

> Закрытый набор вариантов TrioError определён в TTB-Spec §7 (v0.2: 16 кодов
> ядра + 3 транспортных файловых кода, см. патч TTB P-07) и не дублируется здесь.

## TTB v0.1 → v0.2

### P-06. Граничная конвенция R-INT2 (дополнение §3)

> R-INT2 (граница моста): `|v| <= 2^53 - 1` — OK; `v = 2^53` — OK с
> `Lossy(repr)` (граничный маркер); `|v| > 2^53` — `Err(IntRangeOverflow)`.
> Агрегация батчей — по максимуму жёсткости: Err > Lossy > OK.

### P-07. Закрытый набор кодов (замена §7)

> Закрытый набор `TrioError`: 16 кодов ядра — `TypeMismatch, ShapeError,
> DomainError, IntRangeOverflow, FractionalInt, NoCoercion, EncodingFault,
> NaNAsMissing, SentinelDetected, LayoutMismatch, MissingField,
> HeterogeneousMatrix, NullPointer, UnsupportedStreaming, ResourceLost,
> UndefinedBridge` — плюс 3 транспортных файловых кода слоя TRIOMAT:
> `MalformedHeader, MalformedDtype, BoolPayload`. Итого 19 кодов, помеченных
> по слою. Новые коды вводятся только новой версией спеки.

### P-08. Пустая матрица (дополнение §4)

> `0x0` — каноническое `Optional[T]`-empty: OK. `0xk` и `kx0` при k ≠ 0 —
> `Err(ShapeError)`. Интерпретация «0x0 = Optional.empty» фиксируется явно.

### P-09. Таблица маппинга исключений R-ERR2 (дополнение §7)

> Маппинг исключений хоста (Python-слой): `TypeError → TypeMismatch`,
> `IndexError → ShapeError`, `KeyError → MissingField`, всё прочее →
> `ResourceLost`. Точки расширения для java/octave — ◻ (перенести в v0.3).

### P-10. Разведение R-DIM3 / R-DIM7 (правка §4)

> R-DIM3 — только правило унификации по имени. Конфликт значений DimVar
> (`R ≠ R`) и несовпадение ранга — R-DIM7: `Err(ShapeError)` / SC-050
> DimConflict.

### P-11. Контракт API моста (новый §10)

> - `unify` нормализует анонимный `?` в `?N`, N — позиция вхождения (0-based).
> - Layout-маркеры (`"C"`/`"F"`) в унификацию размерностей не входят.
> - `pack_octave`/`unpack_octave` — транскодинг на границе; формат файла
>   layout не хранит (см. патч TRIOMAT).

## triomat v1 → v0.2

### P-12. Вариант Б — свойство канона (см. патч TRIOMAT §2.1)

Payload всегда C-порядок; F- и C-источники обязаны давать байт-в-байт
одинаковый файл; транскодинг живёт на границе моста и журналируется.

### P-13. Переименование `TypeError` → `MalformedDtype` (см. патч TRIOMAT §2.2)

Только файловый слой. Рекордный `TypeError` в SCore/STRUCT не затрагивается.
