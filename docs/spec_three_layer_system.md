# SPEC: Трёхслойная система статической верификации
## Прямая дорога / Sound-машина / Mathmachine

---

## Архитектура

```
КОД
 |
 +---> [СЛОЙ 0: Прямая дорога]  CFG, циклы, разрезы, тривиальные вердикты
 |        |  очередь сложных мест
 |        v
 +---> [СЛОЙ 1: Sound-машина]   инварианты, SAFE / UNSAFE / MAYBE
 |        |  очередь MAYBE с контекстом
 |        v
 +---> [СЛОЙ 2: Mathmachine]    контрпримеры и доказательства, динамика
```

Правила эскалации:
- слой обязан передавать вверх всё, что не смог закрыть, - молчание запрещено;
- каждый верхний слой получает не только вопрос, но и знания нижнего (инварианты, пути, разрезы);
- вердикт нижнего слоя никогда не пересматривается верхним в сторону ослабления:
  UNSAFE остаётся UNSAFE, верхний слой может только уточнить MAYBE.

---

## SPEC-0: ПРЯМАЯ ДОРОГА (быстрый слой)

**Назначение.** Самый дешёвый проход: разобрать программу на граф, найти всё, что видно "с дороги", и подготовить модель для верхних слоёв.

**Вход:** исходный код (или IR), конфигурация проверок.

**Выход:**
- CFG (граф потока управления) с блоками и рёбрами;
- классификация узлов: ациклические пути, циклы (SCC по Тарьяну), хабы-семафоры;
- карта узких мест: разрезы по Push-Relabel, точки отказа;
- вердикты по тривиальным проверкам: явные деления на ноль, очевидные мёртвые ветки, нарушенные порядки захвата блокировок;
- сертификаты: Холл (дефицит паросочетания), разрез (CUT);
- очередь "сложных мест" на верхние слои.

**Алгоритм:**
1. Построить CFG; Тарьян - найти SCC и обратные рёбра (циклы).
2. Прогон Push-Relabel: максимальный поток по ресурсной модели -> минимальный разрез -> список узких мест.
3. Прогон Куна там, где есть парная структура (ресурсы <-> потребители); при дефиците - сертификат Холла.
4. Прямое исполнение ациклических путей: линейные участки считаются честно, без приближений.
5. Всё, что живёт внутри циклов или гонок, - в очередь слою 1.

**Инварианты:** слой не выдаёт вердиктов SAFE/UNSAFE по циклам - только маршрутизацию. Ошибка здесь = потеря производительности, не корректности.

**Сложность:** O(V + E) на Тарьяна, O(V^3) на PR, суммарно линейно-кубично.

**Режимы отказа:** программа без явной структуры - слой отдаёт вопрос вверх, не фантазирует.

## SPEC-1: SOUND-МАШИНА (абстрактный слой)

**Назначение.** Вывести инварианты по всему CFG и закрыть максимум проверок вердиктами SAFE / UNSAFE. Остаток - MAYBE - передать наверх.

**Вход:** CFG от слоя 0; абстрактная область (интервалы по умолчанию, настраиваемо); передаточные функции F_e для каждого ребра; оператор widening.

**Выход:**
- map: узел -> инвариант (после достижения неподвижной точки);
- вердикты по каждой точке проверки: SAFE / MAYBE / UNSAFE;
- для каждого MAYBE - контекст: путь, диапазон значений, какая передаточная функция загрубелила.

**Алгоритм:**
1. Инициализация: вход - ограничения, остальное TOP.
2. Worklist-итерации с передаточными функциями (присваивание - сдвиг границ, условие - сужение, слияние - join).
3. На обратных рёбрах - widening (остановка), затем narrowing (возврат точности).
4. Стоп: очередь пуста = наименьшая неподвижная точка.
5. Вердикты; MAYBE-контексты - в очередь слою 2.

**Инварианты корректности:**
- монотонность всех F_e (проверяется при загрузке области);
- soundness: конкретные значения включаются в инвариант; SAFE и UNSAFE железны, MAYBE - честное "не знаю";
- остановка гарантирована widening'ом.

**Сложность:** O(итерации x |E| x стоимость F); на интервалах - единицы-десятки итераций.

**Режимы отказа:** ложные MAYBE допустимы и являются нормальным продуктом; пропуск реальной ошибки запрещён и возможен только при нарушении контракта F_e.

## SPEC-2: MATHMACHINE (точный слой)

**Назначение.** Взять то, что слои 0-1 не закрыли, и дожать математикой: точные доказательства там, где приближения сказали "возможно".

**Вход:**
- очередь MAYBE-контекстов от слоя 1 с их инвариантами;
- для параллельных участков - модель взаимодействий (позиции, ожидания, ёмкость семафоров).

**Выход:**
- вердикт по каждому MAYBE: либо контрпример (конкретный вход, ведущий к ошибке), либо доказательство безопасности;
- для динамики: достижимость тупика, наличие выхода из каждого ожидания; при взрыве состояний - развёртка с отсечениями.

**Алгоритм:**
1. Уточнение MAYBE: symbolic execution по помеченному пути с инвариантом слоя 1 как ограничением -> система условий -> решатель. Есть решение -> контрпример; нет -> SAFE доказан.
2. Для циклов с нелинейностью: узкая итерация (narrowing) на точной арифметике либо символьный замкнутый вывод инварианта цикла.
3. Для параллельного кода: построить сеть, BFS по пространству состояний; тупик = состояние без исходящих рёбер, кроме финального. Пространство большое -> развёртка: события вместо состояний, cutoff-правила отсекают эквивалентные ветви; soundness сохраняется, полнота частично жертвуется.

**Инварианты корректности:**
- все ответы слоя 2 точны относительно входной модели (контрпример всегда воспроизводим на модели);
- soundness наследуется от модели: если модель пере-аппроксимирует программу - вердикты железны с той же оговоркой.

**Сложность:** решение условий - от полиномиальной до экспоненциальной; поэтому слой запускается последним и только на остатке.

**Режимы отказа:** неразрешимые условия -> честный "не доказано" (не "безопасно"); развёртка с cutoff может пропустить тупик в отсечённой ветви - фиксируется в отчёте.

## Контракты между слоями

```
КОД
 |
 +-+-> [СЛОЙ 0: Прямая дорога]  CFG, циклы, разрезы, тривиальные вердикты
 |     |  очередь сложных мест
 |     v
 +-+-> [СЛОЙ 1: Sound-машина]   инварианты, SAFE / UNSAFE / MAYBE
 |     |  очередь MAYBE с контекстом
 |     v
 +---> [СЛОЙ 2: Mathmachine]    контрпримеры и доказательства, динамика
```

Правила эскалации:
- слой обязан передавать вверх всё, что не смог закрыть, - молчание запрещено;
- каждый верхний слой получает не только вопрос, но и знания нижнего (инварианты, пути, разрезы) - они сужают его работу;
- вердикт нижнего слоя никогда не пересматривается верхним в сторону ослабления: UNSAFE остаётся UNSAFE, верхний слой может только уточнить MAYBE.

## Цепочка soundness (главный инвариант системы)

Каждый слой пере-аппроксимирует программу сверху, и пере-аппроксимация только накапливается, но не исчезает. Поэтому: если вся система говорит SAFE - это гарантия для всех реальных исполнений программы. Цена системы - количество MAYBE, дошедших до вершины; качество - насколько дорогое сведение удаётся сделать на слоях 0-1.

# Формальная грамматика обмена между слоями (EBNF)

Записана в нотации EBNF (ISO 14977): терминалы в кавычках, | - выбор,
{} - повторение ноль и более раз, [] - опционально, () - группировка.
Грамматика описывает только формат обмена; разбор кода программы - вне её рамок.

## 1. Общая структура сообщения

```ebnf
message     = header , body ;
header      = msg_id , ":" , src_layer , "->" , dst_layer , ":" , msg_type , ";" ;
msg_id      = identifier ;
src_layer   = layer_tag ;
dst_layer   = layer_tag ;
layer_tag   = "L0" | "L1" | "L2" ;
msg_type    = "TASK" | "VERDICT" | "MAYBE_QUEUE" | "MODEL" | "CERTIFICATE" | "REPORT" ;
```

## 2. VERDICT - вердикт точки проверки

```ebnf
verdict     = "VERDICT" , "(" , location , "," , class , [ "," , evidence ] , ")" ;
class       = "SAFE" | "UNSAFE" | "MAYBE" ;
evidence    = path | range | counterexample ;
```

## 3. MAYBE_QUEUE - очередь на верхний слой

```ebnf
maybe_queue = "MAYBE_QUEUE" , "{" , { maybe_item } , "}" ;
maybe_item  = maybe_id , "=" , maybe_ctx ;
maybe_ctx   = "(" , location , "," , invariant , "," , hole_kind , "," , parent_chain , ")" ;
hole_kind   = "DIVISION" | "INDEX" | "OVERFLOW" | "RACE" | "UNKNOWN_CALL" | "OTHER" ;
parent_chain = { maybe_id } ;
(* parent_chain: путь уточнений - каждый верхний слой помнит, от какого
   MAYBE нижнего он порождён. Это сохраняет прослеживаемость вердикта
   до исходной точки проверки и поддерживает контракт "не ослаблять". *)
```

## 4. Инвариант - значение абстрактной области

```ebnf
invariant   = interval | top | bottom ;
interval    = "[" , num , "," , num , "]" ;
top         = "TOP" ;
bottom      = "BOTTOM" ;
num         = [ "-" ] , digit , { digit } | "-INF" | "INF" ;
```

## 5. TASK - задание для точного слоя

```ebnf
task        = "TASK" , "(" , kind , "," , location , [ "," , constraint_list ] , ")" ;
kind        = "SYMBOLIC_CHECK" | "DEADLOCK" | "UNFOLD" | "REFINE" ;
constraint_list = { constraint , ";" } ;
constraint  = var , rel , num ;
rel         = "<" | "<=" | "==" | ">=" | ">" | "!=" ;
```

## 6. MODEL - динамическая модель (сеть Петри)

```ebnf
model       = "MODEL" , "{" , places , "," , transitions , "," , capacity_list , "}" ;
places      = "P" , "{" , { place_id } , "}" ;
transitions = "T" , "{" , { transition } , "}" ;
transition  = trans_id , ":" , { place_id } , "->" , { place_id } ;
capacity_list = { "(" , place_id , "," , num , ")" } ;
```

## 7. CERTIFICATE - доказательства и опровержения

```ebnf
certificate = "CEX" , "(" , counterexample , ")"
            | "PROOF" , "(" , location , "," , invariant , ")"
            | "HALL" , "(" , deficient_set , ")"
            | "CUT" , "(" , cut_edges , ")" ;
deficient_set = "{" , { var } , "}" ;
cut_edges   = "{" , { edge_id } , "}" ;
counterexample = "(" , input_values , "," , trace , ")" ;
input_values  = { assignment , ";" } ;
assignment    = var , "=" , num ;
trace         = { step , ";" } ;
step          = location , ":" , statement ;
statement     = ident , "=" , expr ;
expr          = var | num | var , binop , var | var , binop , num ;
binop         = "+" | "-" | "*" | "/" ;
```

Сертификаты - свидетельства, а не вердикты: HALL (дефицит паросочетания) и CUT (минимальный разрез) проходят сквозь систему без изменения.

## 8. REPORT - итоговая сводка

```ebnf
report      = "REPORT" , "{" , summary , coverage , reservations , "}" ;
summary     = "safe=" , digit , { digit } , ", unsafe=" , digit , { digit }
            , ", maybe=" , digit , { digit } ;
coverage    = "coverage=" , pct , "%" ;
pct         = digit , { digit } ;
reservations = { caveat } ;
caveat      = "NARROWING_LOSS"
            | "UNFOLD_CUTOFF"
            | "UNSOLVED" ;
```

Отчёт без перечисления caveat считается некорректным: каждая потеря полноты обязана быть зафиксирована.

## 9. Лексика

```ebnf
identifier  = letter , { letter | digit | "_" } ;
letter      = "a" | "b" | "c" | ... | "z" | "A" | ... | "Z" ;
digit       = "0" | "1" | "2" | ... | "9" ;
var         = identifier ;
location    = block_id , [ "." , stmt_id ] ;
block_id    = identifier ;
stmt_id     = identifier ;
edge_id     = block_id , "->" , block_id ;
place_id    = identifier ;
trans_id    = identifier ;
path        = { block_id , "->" } , block_id ;
range       = interval ;
```

Лексика (location, edge_id, place_id) общая для всех слоёв: один и тот же идентификатор должен означать один и тот же узел во всех сообщениях системы.

## Примеры корректных сообщений

```
m17: L1->L2 : MAYBE_QUEUE ; {
  mb_12 = (b4.s2, [0, 99], DIVISION, {mb_3}) ;
}
m18: L2->L1 : VERDICT ; VERDICT(b4.s2, UNSAFE, CEX((x = 100;),(b4.s1: x = x + 1;))) ;
m19: L0->L1 : CERTIFICATE ; CUT({b7 -> b9}) ;
m20: L2->L0 : REPORT ; {safe=143, unsafe=2, maybe=7 coverage=89% NARROWING_LOSS UNFOLD_CUTOFF} ;
