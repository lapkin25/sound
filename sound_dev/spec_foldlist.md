# Спецификация foldlist — Piano frozen v0.5.1 / реестр v0.5.2

Версия: spec v0.1. Статус: заморожена до байт-в-байт ворот на DemoMax; правки — только записью новой версии.

## 1. Сигнатура и семантика

`foldlist acc f list` — левая свёртка: правило `f` последовательно применяется
к аккумулятору и очередному элементу списка; обход — с головы списка.

    foldlist a f [x1 .. xn] = f( f( ... f( f(a, x1), x2 ) ... ), xn )

Для n = 0 результат — `a`. Для некоммутативного `f` порядок фиксируется:
от головы к хвосту.

- `f` — имя правила с арностью ровно 2: первый параметр — аккумулятор, второй — элемент.
- Разворот явный, в плоскую цепочку шагов. Причина — конструкция стека:
  парсер-эмиттер строит журнал, реплей его воспроизводит; ИНВ-Р.1 (ссылки только
  назад), чекпоинты и рестарт осмыслены именно на плоской цепочке. Семантика
  «цикла как оператора» в журнале не существует.

## 2. Требования к операндам (проверяются статически; категория DictErr)

- `f` — имя существующего правила, арность 2. Иначе DictErr.
- `list` — выражение, статически выводимо списочное и статически выводимой
  длины: литерал списка, имя из data со значением-списком, `snoc`/`cons`/`tail`
  над списочным выражением. В frozen-грамматике нет конструкторов динамической
  длины, поэтому длина любого списочного выражения выводима статически —
  требование проверяемо на этапе разбора.
- Скалярный третий операнд (результат `part`, `len`, `plus`, `lt`, числовой
  литерал) — DictErr «вид операндов».
- `acc` — любое выражение; тип не проверяется транскриптором (соглашение cons:
  типизация — забота реплея, класс «ошибка реплея»).
- Пустой список — легальный вход: ноль итераций, результат — якорь аккумулятора.

## 3. Канон разворачивания (канон DemoMax)

Форма одной итерации фиксирована — шесть шагов скелета плюс шаги тела:

    ref cur -> ?          ; текущий список (остаток)
    const 0 -> ?          ; индексный шаг канона
    part ref idx -> ?     ; голова = элемент
    tail ref -> ?         ; остаток
    ref tail -> ?         ; свежая ссылка на остаток (канон DemoMax)
    <шаги тела>           ; acc <- тело, x <- tid шага part

Решения канона — каждое осознанное и под байт-в-байт воротами:

1. **Обход головой.** Элемент извлекается `part cur 0` из текущего остатка,
   список сжимается `tail`. Альтернатива — бегущий индекс по полному списку
   без tail — отвергнута: канон DemoMax строится на len/tail/ref, обход головой
   делает скелет итерации однородным.
2. **Индексный шаг сохраняется** (`const 0` в каждой итерации), несмотря на
   константность значения: однородность формы важнее экономии шагов.
   Прецедент — «мёртвые» ветви If.
3. **ref перед part и ref хвоста** — как в DemoMax. Лишние ref (дублирующие
   один и тот же список) — вопрос реестра стиля (открытый пункт §9);
   до решения — обязательны.
4. **Uniform-форма последней итерации.** `tail` последней итерации (пустой
   список) и его ref пишутся, хотя следующей итерации не будет. Шаги не
   вычищаются.
5. **Якорь аккумулятора.** Если acc — литерал, эмиттируется `const`
   (`const nil` для пустого списка); если выражение — оно разворачивается
   обычным образом, его последний хендл становится якорем. Первый шаг тела
   первой итерации ссылается на якорь.
6. **Подстановка в тело.** Параметры `f` (acc, x) замещаются tid якоря и
   tid шага `part` соответственно — напрямую, без прокси-ref. Тело встраивается
   с перенумерацией (bind: повторное употребление имени — новые узлы).
7. **Цепочка аккумулятора.** На итерации k шаги тела ссылаются на последний
   шаг тела итерации k-1 (на k = 1 — на якорь). Хендл последнего шага тела
   последней итерации — финальный хендл foldlist.

## 4. Порядок эмиссии

1. Якорь аккумулятора (`const` или хендл развёрнутого выражения acc).
2. Шаги вычисления списка-операнда: если список — data-имя или литерал, один
   шаг `const [...]`; если выражение (`snoc`/`cons`/`tail`), — обычный разворот
   этого выражения.
3. `len` списка.
4. Итерации в канон-форме §3, слева направо.

Точный порядок первых трёх групп закрепляется байт-в-байт воротами на DemoMax:
эталон старше текста, расхождение исправляет текст, а не эталон.

## 5. Пример разворота

Программа (Sound v0.1):

    data A = [3,-1,4]
    rule add acc x = plus acc x
    foldlist 0 add A

Разворот (плейсхолдеры `?`; значения заполняет реплей):

    t0001 const 0 -> ?            ; якорь аккумулятора
    t0002 const [3,-1,4] -> ?     ; список
    t0003 len t0002 -> ?          ; 3
    ; итерация 1: элемент 3, acc 0 -> 3
    t0004 ref t0002 -> ?
    t0005 const 0 -> ?
    t0006 part t0004 t0005 -> ?
    t0007 tail t0004 -> ?
    t0008 ref t0007 -> ?
    t0009 plus t0001 t0006 -> ?
    ; итерация 2: элемент -1, acc 3 -> 2
    t0010 ref t0008 -> ?
    t0011 const 0 -> ?
    t0012 part t0010 t0011 -> ?
    t0013 tail t0010 -> ?
    t0014 ref t0013 -> ?
    t0015 plus t0009 t0012 -> ?
    ; итерация 3: элемент 4, acc 2 -> 6
    t0016 ref t0014 -> ?
    t0017 const 0 -> ?
    t0018 part t0016 t0017 -> ?
    t0019 tail t0016 -> ?
    t0020 ref t0019 -> ?
    t0021 plus t0015 t0018 -> ?

Финальный хендл — t0021, после реплея значение 6. Итерации 1..n однородны:
скелет из пяти шагов (ref, const, part, tail, ref) плюс шаги тела.

## 6. Вложенность и If

- Тело может содержать вложенный `foldlist`: разворачивается рекурсивно,
  счётчик общий и сквозной. Глубина не ограничена — все программы frozen
  тотальны, разворот конечен по построению (длины статические).
- `If` в теле: обе ветви разворачиваются (строгость), выбор — один шаг `if`;
  хендл if-шага — аккумулятор следующей итерации. Невзятая ветвь присутствует
  в журнале («мёртвые» шаги не вычищаются).
- Правило, вызванное из foldlist, может само содержать foldlist; нумерация
  переносится сквозным образом, ИНВ-Р.1 сохраняется по построению.

## 7. Инварианты, контроль, ошибки

- ИНВ-Р.1: все tid-ссылки — строго назад; литеральные аргументы `const`
  (nil, числа) ссылками не считаются. В канон-форме foldlist инвариант
  выполняется структурно.
- Дедупликация запрещена: `const 0` каждой итерации — отдельный узел; значения
  списков выписываются целиком.
- GrammarErr — до семантики; DictErr — до эмиссии (§2); TranscrErr — защитный
  слой на случай нарушения структурных инвариантов разворота (в frozen-грамматике
  почти недостижим). Типовые ошибки (например, список вместо числа в теле) —
  класс «ошибка реплея», не парсера.
- Реплей сверяет значение `len` со статически выведенной длиной — дублирующая
  проверка, дешёвая и обязательная.

## 8. Распределение ответственности

| Слой | Обязанность |
|---|---|
| Транскриптор (парсер) | статический вывод длины, канон-форма, нумерация, плейсхолдеры ? |
| Реплей | значения шагов, типизация, ИНВ-Р.1 по значениям, отпечаток |
| Дублёр | независимое вычисление финала для сверки |

## 9. Открытые пункты

1. Форма итерации и порядок эмиссии — закрепляются байт-в-байт воротами
   на DemoMax: эталон старше текста.
2. Индексный шаг: `const 0` при обходе головой против бегущего индекса —
   закрепляется теми же воротами.
3. Лишние ref — реестр стиля: обязательный канон или допустимая оптимизация.
4. Вложенная свёртка на результате foldlist'а (список, построенный телом,
   скормленный новой свёрткой) — допустима в frozen (статическая длина);
   канон разворота тот же, но кейс для неё пока не поставлен.
