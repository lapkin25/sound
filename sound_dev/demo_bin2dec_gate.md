# DemoBin2Dec — протокол ворот

## 1. Постановка
Перевод двоичного числа bits = [1,0,1,1,0,1] (MSB->LSB) в десятичное значение.
Ограничение реестра: нет умножения и деления. Решение — схема Горнера через удвоение:
acc' = 2*acc + bit, где 2*acc = plus acc acc, добавление бита — через if (lt 0 x).
Десятичные ЦИФРЫ результата не получить (нет div/mod) — out есть само значение.

## 2. Исходник (sound v0.1)
```
# DemoBin2Dec — перевод из двоичной системы счисления в десятичную
# sound v0.1, грамматика v0.5.1 (frozen)

fact n  = 6
fact b0 = 1
fact b1 = 0
fact b2 = 1
fact b3 = 1
fact b4 = 0
fact b5 = 1

fact bits = snoc (snoc (snoc (snoc (snoc (snoc nil b0) b1) b2) b3) b4) b5

rule step acc x = If (lt 0 x) (plus (plus acc acc) 1) (plus acc acc)

out dec = foldlist step (const 0) bits
```

## 3. Эмиссия (канон v0.3, маркер sound-0.5.1)
- сборка bits: 13 шагов (const nil, 6x const, 6x snoc)
- len корня: 1 шаг, непотреблённый — канонно (прецедент DemoMax)
- якорь (const 0): 1 шаг
- 6 итераций по 10 шагов: скелет ref/const/part + тело из 7 шагов
- итого 75 шагов; в 0.5.2-каноне было бы 68 (минус 6 ref, минус len)

## 4. Реплей
75/75, ноль расхождений. Финал t0075 = 45. Независимая проверка: 101101_2 = 45.

## 5. ИНВ-Р.1 и потребители
Нарушений нет, все ссылки назад. Потребители корня t0013: 7 (len + 6 ref).
Мёртвые узлы: t0014 (len) — канонно; t0075 (if) — результат out.

## 6. Канон-решения, вытянутые кейсом
- О.1 (гипотеза, требует арбитража): deref и len привязаны к маркеру формата.
  sound-0.5.1 -> ref перед каждым part + len в скелете (DemoMax, DemoReverse);
  sound-0.5.2 -> part напрямую, без len (DemoReverse2). Все четыре эталона согласны.
- О.4 (требует арбитража): ветки if вычисляются жадно — иначе у if нет хендла
  невзятой ветки, а формат требует два handle-аргумента. Литeралы тела правила ->
  шаг const на каждую итерацию (шаг на узел AST; прецедент — двойной nil в DemoReverse2).

## 7. Статус
Исходник и журнал порождены в этом контуре — ворота самоссылочные.
Внешний якорь один: значение 45. Ожидается арбитраж арбитра: значение, структура,
решения О.1 и О.4. После подтверждения журнал фиксируется как эталон кейса.
